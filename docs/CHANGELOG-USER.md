# What's New for Users

- The site had already worked out the licence for tens of thousands of wiki-hosted user scripts and gadgets, and then never showed you a single one of them. A page published on a Wikimedia wiki carries the licence the terms of use imposed on the day it was first written — which is why the answer has to be worked out per page rather than assumed for the whole set — and 43,529 entries had that answer stored. The catalogue was reporting the licence as known for about one entry in ten. It should have been closer to three in four. The same silence covered titles, links and the list of wikis a script runs on: 41,826 entries were sitting on newer information than the page describing them ever showed.
- The reason was that nothing ever told the catalogue. The part of the site that assembles what you actually see rebuilt an entry when the software that builds it changed version, when a previous attempt had failed, or when a source repository had been analyzed again — and never when the hourly scan of a wiki had just found something new. A script renamed, newly documented, or given a different licence on its wiki therefore kept its old entry indefinitely, and the only thing that ever cleared the backlog was an unrelated version change. The scans now report which entries they changed, and those are rebuilt straight away. Entries that did not change cost nothing, so the hourly scans are no slower than before.
- User scripts are now credited to the wiki that hosts them. Until this release all 37,863 of them were presented as though Toolhub had asserted every detail — the title, the description, the wikis it runs on — when Toolhub has never heard of any of them. They are pages on a wiki, and the site now says so on every card and in every evidence panel, at the confidence a wiki page earns rather than the confidence reserved for the official catalogue. Gadgets were already credited correctly; user scripts were simply missed when that was set up, and nothing since had noticed.
- The release that worked out that licence data could not finish installing them. Rebuilding the catalogue's entries happens in large batches, and each batch ends by leaving a one-line note for another job telling it the summary counts need republishing. If a second job happened to leave that same note first, writing it failed — and because the note was written inside the same unit of work as the entries themselves, the failure threw away every entry in the batch. Twenty thousand rebuilt entries were discarded that way, twice, during a single deployment, and the entries were left marked as failed rather than as never attempted. Nothing was lost permanently and the licence figures you see now are correct, but they had to be reinstalled by hand. The note is now written in a way that cannot collide, and a collision could no longer cost anything but the note.
