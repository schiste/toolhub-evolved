# What's New for Users

- Toolhub Evolved now publishes concise English daily, weekly, and monthly digests of newly added tools. Daily editions mention every new tool, every edition covers one closed UTC period, and periods without new tools produce no empty edition. Public browsing now uses the latest complete local catalog generation, reports its UTC freshness, and keeps the previous generation available if synchronization fails; the web process no longer contains a hidden request-time Toolhub fallback. Catalog pages use compact card data, precomputed filters, indexed recent sorting, and non-blocking enrichment so tools appear immediately while secondary filter and maintainer details finish locally. Purpose filters now include Toolhub tasks and audiences, compatible facet names clearly distinguish detected from declared technology, and a new MCP guide provides verified Claude Code, Visual Studio Code, Cursor, and raw HTTP setup. The What's New panel stays closed when no release exists instead of opening an empty announcement. Automatically detected repository details are being updated again: the background analyzer that reads each tool's public source repository had been stopping before it could record anything since 13 August, so newly added and recently changed tools kept only the information they already had. It now downloads only the files it actually reads instead of a full copy of each repository — several times less data per tool, and slightly faster — so large repositories no longer exhaust it. It also no longer waits for an hourly turn to examine a hundred tools at a time: it now runs without stopping, picking up a tool that has never been analyzed about once a second, so a newly added tool is described within moments rather than within the hour, and the waiting list is worked through as fast as it can be filled. Re-checking a repository that has already been analyzed happens about once a minute on its own separate pace, so that endless routine checking can no longer crowd out the tools still waiting for their first look. And a repository large enough to exhaust the analyzer is now set aside and retried later rather than being picked first on every restart, which is what silently stopped the whole thing before.
- Each edition appears as a compact, readable local blog entry and RSS item, while the lightweight archive makes issues easy to scan and Meta-Wiki remains the canonical publication archive with stable pages for sharing and long-term discovery.
- Signed-in users can subscribe by Wikimedia email or by delivery to their talk page on a supported Wikimedia wiki. Both start delivering straight away with no confirmation step to click: signing in with your Wikimedia account already establishes who is subscribing, and Wikimedia only forwards mail to an address you have already confirmed there, so subscriptions left waiting for a confirmation link have been activated for you. Unsubscribe links are signed and appear on every edition, and new subscriptions never backfill older editions. When a subscription cannot be created, the form now shows the reason the server gave — a Wikimedia identity that could not be verified, or an account that does not exist on the selected wiki — instead of an opaque status line, and confirming or stopping a subscription from an emailed link reports failures the same way. A Wikimedia delivery setting that was entered across two lines no longer makes subscribing fail with an unexplained server error: the contact details Toolhub Evolved sends with each request are repaired automatically, a setting that cannot be repaired safely is named so it can be corrected, and no part of a stored credential is ever shown. Email subscriptions no longer fail with "the confirmation email could not be sent" when the digest service account is configured with underscores instead of spaces: both spellings name the same Wikimedia account and are now recognized as one.
- LiftWing's public Qwen 3.6 27B model writes the short editorial introduction and highlights from bounded Toolhub facts. Every highlight must retain verbatim supporting evidence—either the full metadata value or a substantial exact excerpt—and an exact unambiguous tool title is safely resolved to its canonical Toolhub id; invalid or unavailable model output falls back to deterministic factual copy instead of inventing claims.
- Publication and delivery are restart-safe and observable: missed non-empty periods are recovered, deliveries retry without duplication, permanent recipient failures suspend only that subscription, and an hourly audit makes stalled publication or fallback generation visible to operators. Automatic publication now looks back over a recent window — ninety days by default — instead of the entire catalog history, and prepares a bounded number of editions per run, so each daily pass finishes preparing and actually publishes rather than working backwards through years of archive. Editions published long after the period they cover are treated as archive rather than news: they appear on the website, in the feeds, and on Meta-Wiki, but are never pushed to email or talk-page subscribers, so filling in past days, weeks, and months cannot arrive as a burst in anyone's inbox. Older editions prepared by the earlier unbounded pass and never published are retired instead of being released as a backlog. An edition Meta-Wiki refuses outright — because the text contains a link its spam blacklist rejects — is now recorded as blocked and left alone, rather than re-attempted on every publication run and reported as a fresh failure every hour; it is counted separately so it can be corrected editorially once. The hourly health check also stops counting those retired past editions when it looks for degraded writing, so tidying up old archive material can no longer read as a live problem. It now judges that writing by the day, week, or month an edition covers rather than by when the edition happened to be written, so filling in a gap from months ago is reported as the old news it is instead of as today's problem. Between them these had been raising an alarm nothing could clear, which had quietly switched the check off.
- Three explicitly selected historical editions can be published as ordinary website entries to demonstrate the daily, weekly, and monthly formats. They credit LiftWing Qwen transparently and are not sent to Meta, RSS, email subscribers, or talk pages.
- New digest editions identify catalog authors and verified maintainers when known, link each person to the appropriate Toolhub Evolved author or person page, and provide both the official Toolhub record and safe direct-tool link. Unverified, stale, failed, or expired relationships are excluded, and malformed links are omitted without suppressing the edition. A person named only by a tool's plain-text author field is now credited as soon as separate evidence shows they hold that tool, instead of waiting for that catalog field to be read again — which for most tools meant the weekly pass, so people stayed uncredited for days after we already had the proof. Tools whose address uses non-Latin characters now credit their Toolforge maintainers too; one character lost in the official record had left them unattributed. That hourly re-crediting pass now waits its turn when the weekly pass is still running, rather than standing down and trying again an hour later — which, against a pass that can run for the best part of an hour, meant standing down again and again while nothing reported it, costing days of crediting nobody could see was missing.
- Sign-in no longer depends on the background people directory finishing its identity lookups, so an overlapping directory refresh cannot turn a successful Toolhub authorization into an internal-server-error page. Tool cards throughout home, search, people profiles, and the community directory now use proven Toolhub and Toolforge relationships to link every known author or maintainer to their stable person page; unresolved or ambiguous catalog labels remain attribution instead of being guessed as an account identity. Developer account names and shell logins are no longer conflated; public Toolsadmin labels remain attribution until exact LDAP membership and identity evidence corroborate them, old weak verifications are withdrawn automatically, memberships that do not map to a real Toolhub record stay diagnostic, and people with multiple Developer accounts see the union of their tools without errors. Legacy Developer accounts can become verified automatically when an exact Toolhub/Toolforge handle and independent same-tool evidence agree, including current verified maintainer observations whose label has not yet been attached to a person; expired evidence and name matches alone remain ineligible. Wikimedia user-space tools now verify the namespace owner as their maintainer when that owner resolves uniquely to a CentralAuth global identity; authorship is verified independently only when the declared author also matches. A matching Toolforge account is optional identity enrichment and cannot suppress the Wikimedia relationship when it is missing, disabled, ambiguous, or conflicting. A trusted user-space `.js` page is recorded as the tool's Source code in the local catalog view without overwriting an existing declared repository. Ambiguous Wikimedia identities and lookalike domains fail closed. A tool's runtime or Toolsadmin URL now produces only an unverified project hint: verified Toolforge maintenance requires the canonical `toolforge-$PROJECT` name or a valid registered metadata source hosted by that project, and exact-handle evidence is shown only once per role. One exact current attribution matching one structured handle now appears as a blue unverified relationship on the single stable person page; legacy `/by/` links converge on that page, ambiguous raw labels remain plain text, and stale, expired, failed, or withdrawn attributions stay out of all public people views. Person pages now use stable readable addresses such as `/people/christophe-4ced`; existing UUID links remain valid and automatically converge on the readable address. The Statistics page separates tool coverage, verified people, relationship rows, newly verified tools, identity-only people, stale or expiring evidence so real progress is visible without conflating authorship with maintenance access. Normal refreshes consume only recent Toolhub changes; if Toolhub has already dropped the saved cursor, Evolved preserves every still-visible digest event, starts a clean atomic catalog generation, and resumes from a pre-rebuild anchor so changes arriving during recovery are processed next. If the original cursor becomes available again first, Evolved safely abandons the fallback rebuild and continues incrementally. Deployment and scheduled refreshes now wait for one another instead of writing the same catalog generation concurrently. A separate twice-monthly integrity scan checks the complete catalog without making deployments repeatedly download it. My tools now generates a complete, editable `toolinfo.json` for every related Toolhub record and verified Toolforge project, prefilling only exact project-scoped identities and enforcing the canonical `toolforge-$PROJECT` name before copy or download. Many catalog author labels are the real name a developer set on their public Phabricator profile, which Toolsadmin shows instead of the account handle, so those labels never matched any account. Toolhub Evolved now reads the public Phabricator profile page of Developer accounts that already maintain the tool whose author label is unresolved, and uses the real name it publishes to link that label to the right person page. Nothing is searched by name and no credentials are used: only accounts already proven to maintain that specific tool are ever looked up, the read is the same page any visitor sees, and the result is cached so the same profile is not fetched again for months. A real name is accepted only when exactly one account publishes it, no other person already uses it as a public handle, and it is genuinely different from the handle itself; anything ambiguous stays plain attribution text as before. Departed maintainers keep the names they earned, and a developer who later changes their Phabricator real name has the old one retired automatically. Verified maintenance of the oldest Toolforge tools is no longer lost to an incomplete directory index: memberships are now read from each tool's own member list rather than from the per-account reverse index, which had never recorded roughly a sixth of them. Tools whose metadata feed is published by such a project can once again be attributed to the developers who actually maintain them. Being listed in a project's metadata feed is no longer enough on its own to make every member of that project a verified maintainer of every tool the feed names: a feed says who publishes it, not who runs the tools inside it, so a developer is now shown as a verified maintainer only when they also belong to the project the tool itself is served from. The tool's own address decides that, in every form Toolforge has used over the years, so long-standing records are read correctly rather than treated as naming no project at all. Tools listed in someone else's feed keep their unverified attribution instead of gaining a maintainer nobody proved. Author labels are now matched to a person using the people already proven to hold that specific tool, rather than requiring the name to be unique across the whole catalog — a stranger who happens to share a name no longer blocks the match — and spellings that differ only in punctuation are recognized as the same name, so `Lokal_Profil` and `lokal-profil`, or `Bryan Davis` and `BryanDavis`, finally meet. This links 193 previously unresolved author credits across 26 names to the right person page, with no ambiguous cases. The weekly pass that rebuilds the whole directory had grown to fill its half-hour allowance and was being cut off just before it finished, silently, every week; it now has a full hour, so each week's attribution work completes instead of being discarded near the end. That hourly re-crediting pass now waits its turn when the weekly pass is still running, rather than standing down and trying again an hour later — which, against a pass that can run for the best part of an hour, meant standing down again and again while nothing reported it, costing days of crediting nobody could see was missing.
