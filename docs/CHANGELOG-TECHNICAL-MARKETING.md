# Technical and Marketing Notes

- Three lenses, one pass. `_catalog_totals` now returns a `_CatalogTotals` per lens instead of one. A record belongs to `all` and to exactly one of `catalog` / `wiki`, decided by the `source` column already on the row, so `_LensAccumulator.add()` is called twice per record inside the same `yield_per=500` stream. Filtering per lens would have cost two extra full reads of the canonical cache; accumulating costs one extra counter update per row. The measured build before lenses was 1.29s for 16,832 tools, so three documents stay far inside the refresh job's 240s timeout, and peak memory is unchanged because nothing is materialized.
- A lens is a document, not a filter. `_lens_document` recomputes every block against that lens's tool names, re-running `_relationship_statistics`, `_unresolved_attribution` and `_attribution_funnel` for each. Sums narrow by addition, but a coverage ratio does not, and a verified-relationship count needs the evidence tables queried against the narrower set -- none of the three could be re-derived client-side from the combined document. `_Shared` carries the parts that genuinely do not narrow: toolinfo feeds, publishable people, and the definitions text, extracted to a module constant.
- The payload keeps its old shape. `build_snapshot` spreads the `all` document at the top level exactly as before and adds `lenses: {catalog, wiki}` beside it, so a client that knows nothing about lenses reads what it always did. `distributions.createdByYearBySource` is dropped in the same move: `lenses.catalog.distributions.createdByYear` is that series, now surrounded by figures that agree with it.
- `sourceBindings` and `sourceBindingMethods` are the documented exception. `ToolinfoAuthorBinding` is scoped to a feed record and carries no tool name, so it cannot be narrowed to a set of tools. Both are computed once and read the same under every lens, and the docstring says so rather than leaving a reader to discover it from equal numbers.
- Narrowing unresolved labels to `tool_names` fixed a real miscount. The label branch of `_unresolved_attribution` was the one place that ignored the catalog, so evidence rows for `vanished` -- a tool no lens contains -- inflated `distinctLabels` and `unresolvedLabels`. The golden fixture already asserted that evidence for a tool outside the catalog must not be counted, for the relationship twin; the label twin now agrees, and the two lanes' funnels add back up to the combined one, which is the property a new test pins.
- The frontend switch is a re-render, not a request. `statisticsHTML(payload, lens)` stays pure; `mountStatistics` holds the loaded payload and the chosen lens, and the delegated `change` handler replaces the report markup and moves focus to the new radio, since the one the reader just used no longer exists. Rendering all three documents at once and toggling with CSS -- the trick the old chart-local switch used -- was rejected at page scale: three copies of the report means three copies of every `id`. A snapshot cached before lenses existed renders with the control withheld rather than falling back, so no option can quietly label whole-catalog numbers "wiki".
