# Technical Release Notes

- `catalog-sync`'s recent lane reported `recent_errors=20 recent_tools=0` for 435 consecutive runs while exiting zero and printing `phase=steady completed=True`. Twenty is exactly `MAX_RECENT_DETAILS_PER_RUN`; a probe found the leading twenty of 5325 queued names were tools deleted upstream, answering 404. `_is_gone` now splits 404 out of the retry path -- counted as `recent_gone` and dropped from the queue -- while every other failure stays queued. The summary gains `recent_error_reasons`, a `reason:count` token, because a bare count could not tell twenty deleted tools from twenty timeouts.
- The same lane's cursor hunt is now capped at `MAX_RECENT_SCAN_PAGES` (200 pages, 10000 events). `/api/recent/` is offset-paginated over a feed that only grows, so a cursor sought while events arrive moves down as fast as the scan walks toward it. Recovery through `RecentCursorLostError` was already written and tested and is bounded; only nothing ever declared the hunt hopeless.
- `recentTextFiltersMatch` in `views/recent.js` appends a row's `toolsAdded` and `toolsRemoved` to the haystack it already builds, guarded by `Array.isArray` so an unnamed row contributes nothing. Every other visible column was already searchable; the named tools became visible text in the previous release and were the only column left out.
- The source analyzer no longer infers `gadget` or `user script` at all. `wiki_sources.wiki_source` already resolves a URL to `MediaWiki:Gadget-*` or `User:X/*.js`, so the namespace settles the type with no confidence to trade, and a checkout that is neither can be neither. This replaces the previous fix, which only made server evidence outrank the guess and so left the guess standing for anything without a server; `SERVER_TECHNOLOGIES` is removed rather than built on.
- The rule behind that mistyping is now case-sensitive, requires the call rather than the name, reads only browser-script suffixes, and accepts a `*.user.js` file from its name. It is renamed `MediaWiki JavaScript`, which is what calling `mw.Api` actually proves -- user scripts and wiki-embedded web apps call the same API a gadget does. The evidence that reached the live projection was a Python docstring in `source_endpoints.py`, a runtime-weight file; it no longer matches at all.
- `resolve_tool_relationships` snapshots the six columns it derives from evidence and writes `resolved_at` and `updated_at` only when the snapshot differs or the row is new. Twelve lock-wait timeouts on `person_tool_relationships` between 2026-08-13 and 2026-08-21 all named the same statement shape -- two timestamps and no data -- which is itself proof that nothing else about the edge had moved. The refresh set is deliberately unchanged: it is collected pre-delete so a person who lost an edge is still refreshed.
- `init_schema` runs `create_all` through `_create_missing_tables`, which catches MySQL error 1050 and retries once. `create_all` checks existence and creates in separate statements, so two jobs starting in the same second both see a table missing and the loser gets an error describing exactly the state it wanted -- then stops, leaving the remaining tables uncreated. The retry re-reads what exists, so one is enough for any number of tables lost to the same collision.
- Two lanes gained the counts that make a zero readable. `maintainer-backfill` reports `pages`, `pagesMissing`, and `listed` beside `maintainers`, which distinguishes 60 tools with no account page from 74 names none of which resolve to an account. The enrichment pass summary carries `requestsByProvider`, so a null `rateLimitRemaining` next to no `github` entry -- a pass that spent nothing at GitHub -- reads differently from a null next to a non-zero count.
