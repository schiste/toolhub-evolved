# Technical and Marketing Notes

- `inference_enrichment.pending` and `userscript_docs.pending` now join `UserScriptDirectoryEntry` on `(wiki, title)`, and the inference pool also excludes `STYLESHEET_MODELS`. Both workers queued all 166,399 `role=script` pages against a catalogue of ~48,700 tools; `userscript_toolinfo.record` reads `docs_title` off the directory entry's own title, so every answer found for a folded copy was written and never read. `coverage()` gained the same join, so `eligiblePages` is the denominator the sweep works through rather than one no run can reach.
- `catalog_validation` folds each due URL to a probe target — `action=raw` dropped, only that pair, only as a whole — groups the due fields by target and records one verdict against every field that folded onto it. Wiki tools publish the same page as `url` and as `repository` with `?action=raw`, so that duplicate was the majority of the job's traffic. `candidates` now counts targets and a new `recorded` counts settled fields; `CATALOG_VALIDATION_LIMIT` rises 200 → 500, which puts the ~345/hr steady-state need inside one run.
- `tool_assets.refresh_candidates` partitions the scan into fetches and settlements. "This tool declares no icon" is decided from two projection columns already in memory, so it never belonged under a limit sized for downloads; settlements get their own bound of 5,000 written in `STREAM_BATCH_SIZE` chunks, and `ready` no longer counts `missing` — it reported 100 icons ready an hour while downloading none.
- `catalog_statistics._catalog_totals` outer-joins `CatalogToolProjection` and prefers `effective_record`. The scan read `CanonicalToolCache.record`, so the described-tools figure was pinned at 4,508 — the tools that arrived from official Toolhub carrying one — and 2,583 inferred descriptions live on the site could not move it. The join is outer because the projection refresh lags the sync by design.
- `people_reconcile` refreshes a conflict only when its `details` changed or `last_seen_at` is older than `CONFLICT_REFRESH_AFTER` (6h). The unconditional two-timestamp UPDATE deadlocked against `people-reconcile-incremental` (MySQL 1213) and cost 21 hours; the job command gains `python -u`, because the four killed runs left no output at all and read as runs that never started. Fourth instance of this defect class in the codebase.
- Also in this range: five whole-entity scans across three jobs now select only the columns their loops read and stream at `yield_per=500`, with three cost-regression tests that attach a `before_cursor_execute` listener and fail if any of them starts reading a field it does not use. Loop bodies are unchanged — a SQLAlchemy `Row` exposes attribute access by column name.
- Test hygiene: the digest delivery tests anchored a fixed 2026-08-12 period against a wall-clock `published_at`, so on 2026-08-27 the gap crossed the 14-day publication-lateness bound — four tests failed for a reason none was about, and the tests expecting zero passed for the wrong one. They now go through `_promptly_published_edition`, which pins the gap.
- Validation: full proxy suite 3312 passed, 25 skipped locally; `ruff check` and `ruff format` clean on `proxy/`. Broker gates `jscpd-python`, `pytest-tools`, `ruff-check`, `ruff-format`, `cspell`, `prettier` and `pytest-proxy` all passed on tree `802452b843aa`.
