# Technical and Marketing Notes

- The gadget query is namespace 8 with a `Gadget-` title prefix, and `min()` over the raw stamps is chronological. `MediaWiki:Gadget-HotCat.js` stores as `page_title = "Gadget-HotCat.js"` in `MEDIAWIKI_NAMESPACE = 8`, so `GADGET_CREATION_QUERY` joins `page` to the oldest `revision` per title and `earliest()` folds a gadget's declared pages down to one value. MediaWiki timestamps are fixed-width `YYYYMMDDHHMMSS`, so string comparison is date comparison and no parsing is needed to pick the oldest; `wiki_replica.iso_timestamp` converts only at the publishing boundary, returning `""` for anything that is not fourteen digits. `MediaWiki:Gadgets-definition` is plural and correctly does not match the prefix.
- Stamping is monotone-decreasing and pages by row id. `apply_dates` writes only when the stored value is blank or the computed stamp is strictly older, so a gadget whose declaration gains a page converges to the true creation date and a declaration that loses one does not push the date forward. `record()` walks `wiki_gadgets` by id in batches of `BATCH = 500` rather than repeatedly asking "what is still blank": a page the replica has no row for would answer that question the same way forever and reappear in every batch. `backfill()` is best-effort by construction -- no replica credentials returns `{}`, a `dbnames_for` failure returns `{}`, and a single wiki that fails is skipped with `continue` -- because a census tick must not be lost to a replica hiccup.
- `created` is an ordering key and `created_at_wiki` is a fact; they are deliberately two fields. `userscript_projection._sort_key(discovery_rank)` mints a date-shaped stand-in prefixed to sort behind every real date, and publishing it would have put strings like `00000000-0000000009919` in front of readers as creation dates. `Candidate` gained `created_at_wiki` alongside it, `candidates()` emits both, and `_write` reads the date off `origin.original` rather than the copy that files it -- covered by a test that asserts the stored value is empty _and_ is not `_sort_key(7)`, which a single-field design could not distinguish.
- No migration: additive DDL plus two passes that rebuild what they own. `db.py` adds a `created_at_wiki` string column, thirty-two characters, not null, defaulting to empty, to `user_script_directory` and `wiki_gadgets`, the user-script projection rewrites directory entries whole on every run, and `gadget_census` calls `gadget_creation_dates.backfill` between the inventory and catalogue passes, logging `gadget-creation-dates: wiki=… replica=yes|no stamped=N`. The ordering is asserted in `test_gadget_census.py` because dates must be present before the catalogue pass reads them. User scripts needed no backfill pass at all -- `UserScriptPage.created_at_wiki` was already complete, the value was simply never spent on anything but sorting.
- `createdByYear` gained a per-source sibling rather than a query parameter. `build_snapshot` widens its select to `(tool_name, record, source)`, partitions on `WIKI_SOURCES = (SOURCE_WIKI_GADGET, SOURCE_WIKI_USERSCRIPT)`, and ships `createdByYearBySource: {catalog, wiki}` next to the existing combined series; the toggle is three pre-rendered panels and a delegated `change` listener setting `data-created-source`, so switching costs no request and no redraw. A payload without the new key still draws the combined series and leaves the other two panels empty, which is what an older cached snapshot will do.
- The `calendarDate` rename was forced by the bundler, not by taste. `tools/bundle_modules.py` flattens ES modules into a single scope and raises `BundleError` on a top-level name collision, which `test_build_dist.py` caught: `whats-new.js` already had a private `dateLabel` with different semantics (medium date plus short time, translated unknown-date fallback). Renaming the new shared export was the smaller change. Three exact-inventory tripwires also had to be updated by hand -- `icon.test.mjs` for the new `calendar` glyph, `fixtures.test.mjs` for the `Tool` shape, and the bundle symbol table -- which is exactly what those tests exist to force.
