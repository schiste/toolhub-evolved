# Technical Release Notes

- Adds a durable digest domain over captured official tool-creation events, immutable edition/tool snapshots, publication state, channel subscriptions, and a restart-safe delivery outbox. UTC day, ISO-week, and calendar-month boundaries are deterministic, generation is idempotent, missed closed periods recover automatically, empty periods are suppressed, and idempotent MariaDB migration widens complete rendered bodies to `MEDIUMTEXT`. Public catalog reads now resolve locally through `/v1/catalog/*`; complete Toolhub snapshots stage by generation and publish in one transaction, failed imports preserve the prior generation, the obsolete request-time HTTP client and revalidation worker are removed, and scheduled workers are the only anonymous Toolhub network readers. Canonical ingestion derives compact card JSON and indexed UTC modification timestamps, background jobs atomically publish global facet aggregates, filtered facets use a covering index and independent endpoint, redundant canonical revalidation is removed, and card rendering no longer waits for facet or summary enrichment. Projection version 4 lifts Toolhub `tasks` and `audiences` annotations without treating API-owned annotations as top-level fields; one shared facet vocabulary preserves legacy `technology` compatibility while exposing canonical `detected_technology`, `declared_technology`, and `ui_language` names across REST and MCP. MCP search uses the atomic local replica, GET `/mcp` returns a structured 405 pointing to a lazy-loaded in-app guide with client-specific configurations, and every new message includes translator documentation. Release notes remain collapsed when no deployment record exists.
- Integrates LiftWing's public OpenAI-compatible `llm-qwen36-27b` chat-completions endpoint with strict Wikimedia host/path/model validation, contact-bearing user-agent headers, bounded timeouts and citation-only payloads, period-wide candidate sampling for busy weekly and monthly editions, Qwen reasoning-tag removal, schema validation, unique supplied-title normalization to canonical tool ids, exact full-field or whitespace-normalized verbatim excerpt evidence checks, and an audited deterministic fallback with sanitized failure details. Daily requests and responses cover every supplied tool exactly once; weekly and monthly responses select exactly `min(total, 5)` tools; omissions, duplicates, ambiguous or invented identifiers, paraphrases, and trivial fragments remain fail-closed. A database-free live preflight exercises production facts through inference, validation, and rendering before deployment.
- Publishes canonical edition pages and the archive tree on Meta through a bearer-authenticated Wikimedia Action API client that restricts destinations, verifies the configured service-account identity, bounds responses, refreshes CSRF tokens, and classifies permanent recipient failures. The same client appends talk-page sections and calls `emailuser` without adding SMTP infrastructure.
- Exposes public edition APIs, local blog routes, per-cadence RSS feeds, authenticated subscription/status APIs, seven-day confirmation links, lifetime unsubscribe links, stable Wikimedia identity checks, bounded delivery retries, and per-subscription suspension without cross-channel impact.
- Adds a compact responsive archive and human-scale edition layout, summary-only archive payloads, accessible subscription controls, localized English strings with translator documentation, immutable permalink and feed discovery metadata, and regression coverage for routes, rendering, confirmation, delivery, RSS, outbound guards, identity trust, and UTC period behavior.
- Schedules publication at 06:15 UTC, delivery every five minutes, and an hourly audit. Job locks reclaim at twice each timeout; audit failures cover missing configuration, recent Qwen fallback, overdue generation, Meta/archive failure, exhausted delivery, and stale validated or queued work.
- Supports operator-selected historical editions through an internal website-only publication state excluded from Meta, RSS, and subscriber delivery, with no preview or automatic selector. Editions freeze canonical author labels and current verified author/maintainer identities, expose only grounded name arrays to Qwen, and render Toolhub, direct-tool, author-index, and stable-person links deterministically across every output; unverified or expired edges and unsafe identity/link data are excluded before the immutable snapshot is rendered.
- Keeps OAuth account and encrypted-grant persistence atomic and independent from the derived people index. Transient database locks retry or return a controlled login error rather than HTTP 500, while identity reconciliation closes its read session before remote lookups and reconnects for the write phase; the hourly identity-only worker likewise completes remote registry requests before acquiring shared people/user row locks. Complete LDAP generations distinguish immutable `uidNumber`, Developer account `cn`, and Unix shell `uid`; SUL binding remains authoritative, while an unbound account can be verified only by an exact cross-provider handle plus independently verified same-tool evidence. Corroboration indexes include both person-bound relationships and active verified unresolved-attribution rows, while excluding withdrawn, expired, and self-generated LDAP projections. Bare handle matches remain candidates, proof records immutable account and shared-tool evidence, and preloaded indexes avoid per-account reconciliation queries. A fingerprinted Wikimedia user-space reconciliation pass validates allowlisted Wikimedia hosts and canonical `User:` URLs, resolves the page owner to one CentralAuth-stable person, and publishes confidence-95 maintainer evidence for namespace control. It independently publishes author evidence only when the declared author matches. Exact Toolforge matching remains optional account binding; missing, disabled, ambiguous, or conflicting Toolforge identities cannot suppress provider-native Wikimedia evidence. Ownership changes withdraw both roles, and unchanged runs perform no writes. Catalog projection version 3 derives validated user-space `.js` URLs as confidence-95 repository evidence, preserving the direct page as Source code without mutating official Toolhub cache rows or replacing an existing canonical repository. Toolsadmin labels remain attribution unless independently corroborated, legacy label proofs are retired idempotently, unmapped memberships cannot invent catalog tools, and multi-account people are read without cardinality failures. Toolforge runtime and Toolsadmin record URLs now emit confidence-60 unverified project candidates; confidence-100 LDAP maintainer edges require a canonical `toolforge-$PROJECT` name or a valid registered toolinfo source hosted by that project. Content-addressed identity and source-attestation policies force obsolete verified URL-derived edges to be reprojected. A read-time exact-handle candidate projection caps confidence at 60, requires one unique current public owner, folds the matching raw label once, and supplies cards, tool details, directories, legacy routes, and stable person profiles from the same canonical relationship view without writing an identity mapping. All public relationship and unresolved-attribution queries exclude failed, stale, expired, and withdrawn rows; audit evidence remains private. People now receive an immutable Unicode-safe public slug with a UUID-derived suffix, collision extension, an idempotent deploy-time backfill, and a unique database index; the one-time backfill preloads occupied slugs and allocates missing values in linear time before creating the index. The person API resolves either canonical slugs or legacy UUIDs and publishes one canonical path to every frontend projection. Projection policies are content-addressed to force rebuilds after algorithm changes, deep recent-event backlogs checkpoint exact markers instead of failing at 20 pages, and complete catalog snapshots retry bounded upstream count races without pruning from an inconsistent generation. Projection refresh invokes the incremental recent-change and rolling-reconciliation path; only the separately scheduled twice-monthly integrity job builds a complete generation. Full source audits serialize source-evidence writers and commit bounded retryable batches instead of holding one catalog-wide transaction, while expected refresh overlaps persist as deferred work rather than false failures. Card summaries retain a compact ambiguity-safe projection of every public author/maintainer identity and observed label while excluding full profiles, and statistics expose distinct tool, person, relationship, verification-transition, identity-only, stale, and expiry units. The private My tools payload preserves many-to-many project/account bindings, while a schema-driven browser editor and repository-shipped agent skill generate, validate, copy, and download complete Toolinfo 1.2.2 records without conflating maintainers, authors, core metadata, or API-owned annotations.
