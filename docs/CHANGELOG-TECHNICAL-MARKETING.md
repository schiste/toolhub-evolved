# Technical Release Notes

- `backend/userscript_toolinfo` writes one `canonical_tool_cache` row per directory original, named `userscript-<wiki>-<owner>-<filename>` and carrying a new `source = wiki_userscript`. That table is what "a tool exists" means here -- cards, facets, search and author edges all resolve names through it -- so the promotion is a row in it rather than a parallel table of correct data nothing renders. The new source is kept apart from `wiki_gadget` because a gadget is declared by the wiki and a user script is inferred from a corpus, and an operator has to be able to prune or trust one without the other.
- Every original is promoted, archived ones included, with the tier carried in the record as `_lifecycle`. It is deliberately not the toolinfo `deprecated` flag: "deprecated" is a maintainer saying stop using this, `archived` is only this codebase saying nothing it can see loads it, so `statusOf` ranks archived below both maintainer-set flags and renders a neutral grey badge.
- `canonical_tool_cache.lifecycle` is derived from the record by the model's validator, the way `search_text`, `card_record` and `modified_at_sort` already are, so the record stays the single account of it. It is left without an index on purpose: `_upgrade_schema` adds columns to a live table but never indexes, so a model-level `index=True` would build it in the test database and nowhere else, hiding a slow query until production.
- The stylesheet filter reads MediaWiki's `content_model`, never the suffix, because the two demonstrably disagree -- frwiki serves `User:Penquista/monobook.css` as `javascript`. 39% of the directory's candidates are stylesheets; they stay in the directory and are excluded from the catalogue, with `stylesheet`, `unnamed`, `duplicate` and `conflicted` counted into the job log rather than left as an unexplained difference between two numbers.
- Fork detection is no longer an exact hash. Every page carries a bottom-k MinHash sketch of its body over 5-line shingles, and a page more than 0.9 of the way to an earlier one is filed as a `fork` of it: 3,074 pages across three wikis, 1,428 of them `.js`, in groups the filename rule could not reach.
- `demand()` now ignores a load from anywhere in the target owner's own space rather than only a page loading itself. That removed 44% of enwiki's pages-with-demand, 40% of frwiki's and 37% of meta's -- an author loading their own script was that large a share of the signal.
- `CROWDED_OWNERS`, `INDEPENDENT_DEMAND` and the tier split were re-measured against enwiki, meta and frwiki together, with the same-owner rule and the near-copy fold both in place -- the state neither was originally calibrated in. All three hold and none moved: the crowd curve is convex about 5 on every wiki, the guard's largest rescue is at 1 on every wiki, and the active share lands at 27.4%, 27.7% and 29.4%.
- `backend/wiki_prefixes` reads each wiki's namespace names, aliases and interwiki map from `meta=siteinfo` and hands them to the title fold, so `Benutzer:X/y.js` and `en:User:Lupin/popups.js` resolve to the page and wiki they name. Alongside it, an argument that names no page now produces no edge at all instead of an unresolvable one, and `mw.loader.load('ext.gadget.x')` is recorded in `target_module` rather than misfiled as a title.
