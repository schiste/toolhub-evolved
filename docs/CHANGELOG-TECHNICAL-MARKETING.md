# Technical and Marketing Notes

- Every bounded sweep said "how much work" with a hand-picked item count, which has to be guessed from a per-item cost nobody remeasures. Measured on 2026-08-27, the nine of them ran at 0.1% to 12% of their scheduled interval against five-figure backlogs. `wiki_schedule.Budget` — the monotonic-clock deadline already proven on the census lanes — moved to `backend.run_budget` and now bounds `catalog_validation`, `tool_assets` and `inference_enrichment`: the run works until its allowance is gone, self-tunes to today's cost, and cannot spill into the next tick. The limits stay as runaway guards.
- Each of those jobs declared its allowance twice, and the code copy won silently: `CATALOG_VALIDATION_LIMIT=500` sat against `MAX_CHECKS=500`, so the manifest value had never once done anything. Raising the environment variable alone would have changed nothing, which is the failure mode worth remembering. Timeouts rose with the allowances (300→1200, 600→900, 2100→2700, `--stale-after` at twice each), because a timeout at or below the deadline is a race, and only one of its two outcomes writes the work it just paid for.
- `inference_enrichment.sweep` runs `LIFTWING_CONCURRENCY` calls at a time through a `ThreadPoolExecutor`, checks the budget between waves and commits one transaction per wave; `_ask` is the pure-network half and never touches the database, and `liftwing_caller` keeps a thread-local `requests.Session` so a wave reuses its connections. Six is deliberately modest — Lift Wing is shared and publishes no concurrency figure for the llm-\* surface — and lives in jobs.yaml so it can be moved without a deploy, capped at 24 in code. Its test blocks the fake endpoint on a `threading.Barrier(3)`, so a serial implementation deadlocks rather than passing.
- `inference_enrichment.pending` and `userscript_docs.pending` now join `UserScriptDirectoryEntry` on `(wiki, title)`, and the inference pool also excludes `STYLESHEET_MODELS`. Both workers queued all 166,399 `role=script` pages against a catalogue of ~48,700 tools; `userscript_toolinfo.record` reads `docs_title` off the directory entry's own title, so every answer found for a folded copy was written and never read. `coverage()` gained the same join, so `eligiblePages` is the denominator the sweep works through rather than one no run can reach.
- `catalog_validation` folds each due URL to a probe target — `action=raw` dropped, only that pair, only as a whole — groups the due fields by target and records one verdict against every field that folded onto it, in one transaction rather than one per field. Wiki tools publish the same page as `url` and as `repository` with `?action=raw`, so that duplicate was the majority of the job's traffic. `candidates` now counts targets and a new `recorded` counts settled fields.
- `tool_assets.refresh_candidates` partitions the scan into fetches and settlements. "This tool declares no icon" is decided from two projection columns already in memory, so it never belonged under a bound sized for downloads — and it stays outside the new deadline for the same reason, which is the same mistake made in the other direction. Settlements get their own bound of 5,000 written in `STREAM_BATCH_SIZE` chunks, and `ready` no longer counts `missing`.
- `catalog_statistics._catalog_totals` outer-joins `CatalogToolProjection` and prefers `effective_record`. The scan read `CanonicalToolCache.record`, so the described-tools figure was pinned at 4,508 — the tools that arrived from official Toolhub carrying one — and 2,583 inferred descriptions live on the site could not move it. Separately, `people_reconcile` refreshes a conflict only when its `details` changed or `last_seen_at` is older than `CONFLICT_REFRESH_AFTER` (6h); the unconditional two-timestamp UPDATE deadlocked against `people-reconcile-incremental` (MySQL 1213) and cost 21 hours. Fourth instance of that defect class here.
- Also in this range: five whole-entity scans across three jobs now select only the columns their loops read and stream at `yield_per=500`, with three cost-regression tests that fail if any starts reading a field it does not use; the three pure-database repair sweeps keep counts rather than deadlines, raised to 20,000/20,000/5,000 against measured per-row costs of 0.049s/0.046s/0.009s, and the graph-enrichment manifest test now asserts `limit * SECONDS_PER_TOOL < timeout` instead of two hardcoded numbers. Validation: full proxy suite 3370 passed, 25 skipped locally; `ruff check` and `ruff format` clean on `proxy/`.
