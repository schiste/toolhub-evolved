# Technical and Marketing Notes

- `deprecated` and `experimental` are columns on the canonical cache now, derived where every other denormalized column is. Both are assigned in the `@validates("record")` hook in `models.py` beside `lifecycle`, so the projection has one definition and a backfill re-assigns `row.record` rather than recomputing anything. They are `BOOLEAN NULL` rather than `NOT NULL DEFAULT 0` deliberately: a false-by-default column is indistinguishable from a tool that genuinely is not deprecated, so a partial backfill would look finished and quietly count too few, whereas NULL is exactly "this row predates the column" and needs no meta marker of its own. `backfill_status_flags` therefore uses the data as its cursor, walks `batch_size` rows at a time ordered by `tool_name`, and returns what it has on `SQLAlchemyError` instead of raising — it runs from `migrate.py`, where an uncaught error aborts a deploy after the host has already pulled, and it walks a 17k-row table against a sync job that rewrites it every few minutes. Stopping is safe precisely because the cursor is the data: whatever is still NULL is picked up next deploy, and the read path already treats NULL as "not flagged".
- One `status_predicate` answers the Status group everywhere it is read. It lives in `catalog_facets`, which both `catalog_read` and `canonical_tools` already import and which already owns `default_population()`; the direction is forced, since `catalog_read` imports `canonical_tools` and cannot be imported back. `_filtered_statement`, the facet counts and the offline fallback at `/v1/canonical/tools/` all go through it — the fallback previously honoured `include_archived` alone, so a degraded page answered a filtered search with an unfiltered population. The predicate is an OR of ticked kinds rather than an exclusion per cleared box: chaining exclusions drops a tool carrying both flags from Deprecated and Experimental at once, and with `include_archived=1` admits a purely archived tool under `status=deprecated`. `active` is the complement — `deprecated IS NOT TRUE AND experimental IS NOT TRUE AND lifecycle != archived` — because toolinfo asserts only what is wrong with a tool; archived is named in that complement and again as an OR term of its own, since `include_archived` is the same tick as the Archived box, so a row that reaches the predicate archived was asked for. An absent `status` is every kind and an empty one is none, which keeps a caller that never heard of the parameter on the full population and keeps an untouched search on the short query string the prewarmed cache is keyed on; unknown words are dropped rather than rejected, so a stale bookmark widens instead of erroring. `public_html/views/search.js` lost its client-side filtering loop and the `search.filteredInBrowser`, `search.showingOnPage` and `search.noVisibleOnPage` messages with it: a browser-side filter trims rows out of a page the API has already counted and paged, so `total` and the pager necessarily described a larger set than the one rendered.
- The account-linking pass's skip fast-path fired on a mutual absence. `_link_accounts_to_people` compares `user.person_id` against the person owning the account's Toolhub identifier and skips when they agree — load-bearing rather than an optimization, because relinking restamps identifier rows that need no change, which is the contention the pass was chunked to defer around last release. An account that has never been linked has neither value: the owner lookup returns `None`, `person_id` is NULL, the two agreed, and the row the backfill exists to repair was the one row it always skipped. The comparison now requires `toolhub_owner is not None`, so it matches rather than notices an absence. Unreachable through the site, where login sets `person_id`, but it also made the pass look like a no-op when seeded from an empty database, and it was the last place in this migration where having nothing to do was indistinguishable from being finished.
