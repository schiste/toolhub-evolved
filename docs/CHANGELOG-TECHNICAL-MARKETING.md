# Technical and Marketing Notes

- `tools/deploy.sh` had no idea whether the thing it deployed worked. It verified the manifest and the bundles, then declared success — which is how `/data-layer` shipped an error state to its first visitor and how the deploy that did it reported green. A new `tools/post_deploy_smoke.py` runs against `$BASE_URL` after the restart and asserts four contracts: `/healthz`, `/v1/catalog/health/`, `/v1/config/`, and an anonymous CSRF-less `POST /v1/write/tools/` that must come back 401 or 403 — a write probe that proves the route and its guard are both live without touching production data. Failure prints an explicit rollback criterion naming `$deploy_head_before`, because a smoke check that fails without saying what to restore just moves the outage.
- `proxy/backend/observability.py` supplies the health surface behind that. `/readyz` reports database reachability, `/metricsz` serves Prometheus text, and every request now carries an `X-Request-ID` — accepted from the caller when it matches `[A-Za-z0-9][A-Za-z0-9._:-]{0,127}`, minted otherwise, so correlation cannot be poisoned by an arbitrary header. The counters are deliberately bounded: method × normalized route × status class, with seven latency buckets from 50 ms to 5 s. Route labels come from the Flask rule, never the raw path, so a crawler cannot mint unbounded label cardinality by walking `/tool/<anything>`.
- `.github/workflows/production-monitor.yml` probes production on `7,22,37,52 * * * *` — every fifteen minutes, offset off the hour so it does not queue behind everything else scheduled at `:00`. It has a `workflow_dispatch` input that exercises every documented alert against synthetic unhealthy data, which is the part that matters: an alert nobody has ever seen fire is an assumption, not a check.
- Flask now runs with an explicit `TRUSTED_HOSTS`. It defaults to `toolhub-evolved.toolforge.org`, falls back to loopback when `TOOLHUB_INSECURE_COOKIES=1`, and reads `TOOLHUB_TRUSTED_HOSTS` when set; an empty list raises rather than silently accepting everything, and `register()` takes an explicit argument that wins over the environment. Host-header handling was previously whatever Werkzeug defaulted to, which meant absolute URLs the app generated were derived from a value the caller controlled.
- Two ratchets replace two thresholds nobody was reading. `.python-mutation-ratchet.json` holds a 61.19 % overall mutation score with per-area floors — authentication 87.85, outbound I/O 68.15, data integrity 60.38 — plus hard zeroes for no-tests, suspicious, segfault and interrupted mutants, so a suite that stops running cannot pass by scoring nothing. `.coverage-ratchet.json` does the same for JavaScript at 90.44 / 80.33 / 93.67 / 92.73; the suite currently measures 90.47 / 80.36 / 93.72 / 92.75 across 1,386 tests. Both tools raise with `Math.max` and have no path that lowers a floor.
- The npm audit gate was red the moment it was written, which is the only reason it got fixed. Six advisories, two moderate and four high: `npm audit fix` cleared brace-expansion, fast-uri, js-yaml and nanoid; the remaining `qs` arrived through `typed-rest-client@2.3.1` under `@stryker-mutator/core`, so it is pinned with a narrow `overrides` entry to `6.15.3` — the version `typed-rest-client@3.1.0` itself depends on, and outside the vulnerable 6.11.1–6.15.1 range — rather than forcing a major bump of a devDependency. `tools/python-quality-requirements.txt` now pins the whole Python toolchain so `pip-audit` grades the repository rather than the runner, and CodeQL runs over both languages.
- Translator documentation debt is zero for the first time: 2,523 of 2,523 messages documented. `tools/i18n-extract.mjs` generates baseline context and an explicit `Parameters:` entry per `$n` while preserving human-written guidance, so improving a description survives the next regeneration. `i18n:check` now also rejects an incomplete shipped locale, an empty translation, and any translation that changes the source message's positional parameters — the failure mode where a `$1` silently disappears and the sentence still renders. `.i18n-review.json` starts empty, which is the honest record: no non-English catalogue has been reviewed or shipped yet.
- One thing to flag rather than celebrate: this prefix checks in 1,001 files under `.aethyme/graph/` — a generated repository index, roughly 45,790 lines. It makes Explore work from a clean clone, and it churns on every rebuild — the first CI run on this prefix failed on twenty stale fragments, and refreshing them needs the exact pinned toolchain the workflow builds, not whatever version a developer has installed. If that churn becomes noise in review, the index belongs in a build artefact rather than the tree, and moving it later costs nothing but a `.gitignore` entry.
