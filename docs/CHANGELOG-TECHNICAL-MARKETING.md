# Technical and Marketing Notes

- `MediaWiki:Gadgets-definition` is now read as a manifest, rights and dependencies alike. The scan already located the line registering a gadget in order to learn which pages it consists of, then discarded the rest of it. `gadget_declaration()` returns the parsed entry with the line number and raw text it came from; the analyzer emits one `accessRights` finding per declared `rights=` value and routes each `dependencies=` module through `_put_dependency` in a `resourceloader` ecosystem, so a module naming an API client is read as one by the same rule that reads npm and PyPI clients. Across 487 measured entries, 235 declare dependencies naming 71 distinct modules. The page is classed `manifest` by title rather than through `MANIFEST_FILE_KINDS`, whose values select a dependency parser it must never reach.
- Declared rights and observed calls dedupe into one finding. The vocabulary maps each MediaWiki right onto the same value slug `ACTION_RIGHTS` uses, so a gadget that declares `rollback` and is also seen calling it produces one row carrying both pieces of evidence. The declaration is scanned after the source files, so the category an observed call assigned survives — `_put` sets a category once, on first insertion.
- Declaration-only rights stay outside the write categories, and now have a consumer. `rights=` states an audience gate, not an action, so every declared right is reported under `restricted` at confidence 0.9, just under an observed `action=` call's 0.94, leaving `writeActionsDetected` settled by code that was actually read. `restricted` used to be a category nothing consumed: a gadget gated on `rollback` with no rollback call fell through to permission-clarity's read-only branch and scored 90 — safer than a tool whose code was read. It now takes a 70 branch of its own, and the finding carries a badge in the UI so a declared gate does not render identically to an observed action.
- The vocabulary is measured, and now re-measured on a schedule the data enforces. The first reading of five definition pages found 69 of 488 entries declaring twenty-one distinct rights. Reading fifteen more — the es, ru, ja, it, pl, pt, zh, nl, sv, ar, fa and he Wikipedia editions, meta, en.wikisource and en.wiktionary, 1576 entries — found 36 of 189 declarations naming seventeen further rights, `protect` and `review` among them. Every report now carries `declaredRightCount` and `unknownDeclaredRightCount`, and `repository_scan` logs the rights it cannot describe, so the next nineteen-percent gap announces itself instead of decaying silently.
- Gadget reach travels on the `wikiPage` row, not as permissions. `gadgetDefault`, `gadgetHidden` and `gadgetScope` surface as one neutral permission-clarity signal contributing nothing to the score. Reading `default` alone overstates: of 85 `default` entries only 16 are unqualified, 44 carry `namespaces`/`actions`/`skins`/`rights`/`categories`/`contentModels` limits and 25 are also `hidden`. Keys are absent rather than false when no definition line was read, so "not measured" stays distinguishable from "declared opt-in".
- What the page makes the reader's browser do is now scored and read. `browserPermissions` was collected, listed, and ignored by every health dimension; it gets one of its own at weight 0.7, graded by `browser_permission_reach` — device, browser, or the page the code already runs on — with an extra penalty for an all-sites request. The assessment returns `None` for a tool that asks for nothing, so the dimension is `applicable: false` and no published grade moves. Separately, `.css` files counted against the file budget without being parsed; `@import` and `url()` references to third-party hosts now raise a privacy warning, chosen over the endpoints bucket so `STATIC_ASSET_RE`'s deliberate icon filter stays intact.
- Archived tools left the default search population. `catalog_read` selects `catalog_facets.default_population()` unless `include_archived` is set, and that parameter also forces real facet counting because the cached aggregate is built over the default population only. The page-size controls were also deduplicated into `public_html/lib/core/paging.js`: `PAGE_SIZE_OPTIONS` is Fibonacci 8..144 with `DEFAULT_PAGE_SIZE` 21, replacing the `[12, 24, 48]`/24 triple that search, authors and accounts each declared separately. 144 is the ceiling `MAX_PAGE_SIZE` and the `maximum=` arguments in `v1_accounts.py` and `v1_people.py` clamp to, and they clamp silently — an option above it would render pages the pager counts but the API never returns, so both ends move together or neither.
- Feature-status artifacts were regenerated against what the analyzer does now. The source-analysis entry listed a bucket set two releases stale; automatic repository and on-wiki analysis, the worker behind the repository-analysis provenance label, had no entry at all.
