# Technical Release Notes

- Adds `gadget_inventory`, which reads `MediaWiki:Gadgets-definition` and stores every gadget a wiki declares in `wiki_gadgets`. That page is the entire inventory, so a wiki costs one request where the user-script census costs thousands. An unreadable or empty page retires nothing: silence is not a statement that a wiki's gadgets are gone, and treating it as one would empty the inventory on the first bad response.
- Adds `gadget_toolinfo`, which synthesizes a toolinfo-shaped record per declared gadget into `canonical_tool_cache` under `gadget-<wiki>-<gadget>` with `source = wiki_gadget`. Writing into that table is what makes a gadget a tool everywhere at once — `catalog_projection.refresh_candidates` takes the tool universe from it, so cards, facets, search and statistics follow without a second code path. It emits no description, licence or audience, only transcriptions of what the definition page states.
- Scopes `canonical_tools` pruning to official rows. A full catalog snapshot deleted every row from an older generation, which was correct while Toolhub was the only writer and would have erased all synthesized records on the next sync: upstream absence is authoritative only for rows that came from upstream. The snapshot size check is scoped the same way, so synthesized rows cannot mask a short snapshot.
- Dispatches projection provenance on the canonical row's own `source` instead of labelling every row `official_toolhub`, and adds `wiki_gadget_definition` at confidence 90 with a display label in both frontend source maps. A wiki is authoritative about what it deploys, so it outranks a `toolinfo.json` found by guessing at an origin, and sits below anything a person wrote, since a gadget definition states deployment facts and never claims to say what a tool is for.
- Derives catalogue names through one lowercase alphabet with Unicode format characters stripped, so two spellings production MySQL considers equal cannot reach the primary key looking different. Genuine slug collisions are counted as duplicates rather than silently overwriting, and a name already held by a record from another source is never overwritten. Language detection casefolds the suffix test, matching the definition parser, so a gadget shipping `Foo.JS` keeps its language.
- Schedules `gadget-census` daily at 04:09 UTC over `fr.wikipedia.org` and `meta.wikimedia.org`. The catalogue pass runs after every read including a failed one, because it talks to no wiki and rebuilds from stored inventory, so a change to what counts as a tool takes effect on the next tick. Gadget records carry no `modified_date`, so `modified_at_sort` stays null and they cannot flood a recently-changed listing.
- Reports `listActivityAvailable` on the recent feed so a cold catalog replica reads as policy rather than a fault. List activity fails closed against the published-list allowlist, so a replica that has not caught up withholds every upstream list revision. The flag states the replica condition and nothing more: a count of withheld rows would itself disclose that an unpublished list changed, which is the leak the filter exists to prevent, and a rejected fetch carries no flag so an offline reader is not told the replica is at fault. Resolving the allowlist once per batch through a lazy cache also stops a thirty-row feed re-parsing every cached `/api/lists/` page thirty times.
