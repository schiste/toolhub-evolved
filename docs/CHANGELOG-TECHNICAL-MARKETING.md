# Technical and Marketing Notes

- `/recent` published a feed up to a day stale, and the replica was faithfully serving what it fetched. Toolhub answers with `Vary: Accept, Accept-Language, Cookie, Accept-Encoding` and no `Cache-Control`, so `Accept: application/json` is its own Wikimedia CDN cache object — one almost nothing else requests, and therefore one nothing else revalidates. Measured from Toolforge with the prewarmer's own client and User-Agent, same URL, same minute: `application/json` returned Age 71699s (19.9h) and revision 123470; `application/json, */*;q=0.9` returned Age 2353s and revision 123504.
- The fix is one header. The wildcard fallback puts the request on the variant real traffic keeps warm, while JSON stays preferred so content negotiation is unchanged — `/api/schema/` still answers `application/json`, where a bare `*/*` returns OpenAPI YAML and would poison that entry. `Cache-Control: no-cache` and `Pragma: no-cache` do not dislodge the starved variant; no ETag is stored for this URL, so conditional revalidation was never involved.
- A cache's freshness metadata describes the fetch, not the payload. The stale row's `fetched_at` was three minutes old while its body was twenty-six hours old, which is why the only honest check was reading a revision id out of the stored body and comparing it against a live one. The measurement, not the timestamp, is what closed this.
- `viewDiffStub` is replaced by `viewToolDiff`, routed as `/tools/:name/history/:from/:to`, rendering the replica's RFC 6902 operations as a field/operation/value table with JSON Pointer paths resolved to readable names. `/recent` action cells and tool history rows link in through the `parent_id -> id` pair each row already carries, so a diff link costs no additional request.
- The catalog catch-all never fetches on the request path — a miss is a 503 by design — so `cache_prewarm.prewarm_tool_diffs` warms the diffs the current `/recent` page links to, capped at 30. A comparison outside that set reports "not available from the local replica" rather than "no field changes": an empty operation list is a real upstream answer, and conflating the two would report a missing read as a verified absence.
- Two adjacent changes were forced rather than chosen. `route-styles.test.mjs` now answers each (view, class) question once — it compiles a regex and rescans a module per call, and the new rules pushed it past the 5s budget with the assertion unchanged. The i18n documentation ceiling drops 1996 to 1986, because all 17 new keys ship documented instead of as TODOs.
- Validation: all seven broker gates green on the merged tree, including `js-quality` and the full `pytest-proxy` suite. 154 view tests across view-tool, view-router and view-parity; 12 in `test_cache_prewarm.py`, three of them new, one pinning the Accept header so the starved variant cannot be reintroduced silently.
