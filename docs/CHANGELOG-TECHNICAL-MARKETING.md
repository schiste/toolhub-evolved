# Technical and Marketing Notes

- `break: 100` in `stryker.conf.json` was never a threshold; it was a constant. One number cannot describe a matrix whose shards measure 22% to 100%, and set at 100 it failed all nine, every run on record. A gate that is always red carries no information, and the configuration had drifted into describing an app that does not exist -- the config note, the workflow header and the README all claimed a literal 100% score, wrong by 30 to 78 points. The workflow's own comment had already adapted to it in passing ("Stryker always exits non-zero while `break: 100` stands"), which is what a dead gate looks like from the inside.
- It is replaced by a per-shard `floor`, seeded from what each shard actually measured on CI and enforced by the workflow's own awk -- Stryker has no CLI flag for thresholds, so there was nowhere else to put it. `organisms-qv` floors at 82 rather than the 100 it reported, because 24 of its 141 mutants left the denominator as RuntimeErrors: a memory cap that stops mangling that shard must not read as a test regression.
- Eighteen files matched the config's `mutate` glob and no shard's `--mutate`, so nothing ever mutated them while the score implied otherwise -- four of the largest views among them. The failure is silent by construction: a file nobody mutates produces no score, no warning and no missing job, only a number that is smaller than it should be in a report nobody diffs. `tests/unit/mutation-shards.test.mjs` now fails if a file the config mutates is claimed by no shard, or by two.
- The `core` shard is 5741 lines and had never once reported a score -- every run on record is killed at exactly the 60-minute job ceiling. No threshold could ever have applied to it. It splits four ways along the carve-out idiom `organisms-*` already used, so `core-rest` keeps the wildcard and adopts new files the day they are added.
- Two tests read the Stryker sandbox as if it were the source tree, and a test that fails during the dry run aborts the entire shard. `route-styles` scanned instrumented files several times their authored size and blew the 5s timeout; `graph-layout-worker` asserted a 2,000-node layout finishes inside 5s, which instrumented takes about 6s -- and vitest killed the test at that same 5s before the assertion was even reached. Ten views had stopped being mutated over one stopwatch. Both now escape the sandbox for exactly the assertions that cannot hold there, and keep every assertion that still kills mutants.
- Floors were read from CI's own `::notice::score` annotations rather than measured locally, because the two disagree badly: `styleguide` scores 22.13% on CI and 2.04% on the development machine for the identical 1374-mutant set. The workflows pin `node-version: 22` and `package.json` carries neither an `engines` nor a `volta` field, so nothing holds a local checkout to the version CI uses. That gap is the prime suspect and is not yet confirmed.
- Verification: all 15 shards dry-run clean, including the one that was failing two runs in three. The guard test was confirmed to fail on an unclaimed file, a doubly-claimed file, and a scope naming a path that does not exist. The floor comparison was exercised against real report lines -- 22.13 over a floor of 22 passes, 21.99 fails, a missing summary line errors rather than passing silently, and a non-zero Stryker exit still wins. 1326 unit tests pass.
