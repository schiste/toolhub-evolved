# Technical Release Notes

- Four `people_reconcile.py` modes contend for one MariaDB `GET_LOCK`, and every schedule that uses it fires on the minute: `* * * * *` at :00 of each minute, `43 * * * *` at :43:00, `13 5 * * 0` at 05:13:00. They do not run one after another, they race at the same instant on every run. Only `--reconverge` passed a non-zero timeout to `GET_LOCK`; the rest passed 0 and treated a miss as a successful no-op.
- The recorded runs make the cost visible. `--identities-only` lost the lock on 62 of 232 runs (26.7%) and the weekly `--apply` pass on 2 of 11, against 3.6% for `--reconverge` -- the same shape of hourly job, differing only in that it waited 120s. That contrast is the closest thing to a controlled experiment the logs contain, and it set the number.
- On 2026-08-23 the weekly pass reclaimed its `job_guard.sh` file lock correctly (a 480308s-old lock, its normal weekly cadence), then lost the advisory lock to the per-minute drain and exited in 4s emitting `{"locked": true}`. Exit code 0, `lastRunAt` recent, so the workers page read it as healthy -- a run that acquires nothing is indistinguishable from a successful sweep in every signal that page consults.
- The wait is now set by the gap to the mode's own next attempt rather than by the size of its workload: `--queue` 0s, the two hourly modes 120s, `--apply` 600s. The prior comment justified the single wait with "the full pass is the run everyone else is waiting on", which had the contention backwards -- the full pass is the mode most often turned away, and the only one that pays a week for it.
- `--retirements` and a bare dry run have no schedule at all, so nothing retries them; they route to the full-pass wait for the same reason it does. `GET_LOCK` returns immediately on a free lock, so every value here is a ceiling paid only under contention, against a drain that holds for 6-11s -- 600s leaves the weekly pass 3000s against a 2062s worst recorded run.
- `tests/proxy/test_job_runner.py` derives the ordering, the per-job timeout headroom and the drain boundary from `jobs.yaml`, so a moved schedule or timeout fails rather than silently invalidating the constants. Every assertion was checked against the defect it exists to catch: reinstating `full pass waits 0` fails two, giving the drain a wait fails the ordering, exceeding half a job's timeout fails the headroom test, routing `--retirements` to the hourly wait fails the routing test.
