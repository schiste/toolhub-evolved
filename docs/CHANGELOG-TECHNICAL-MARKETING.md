# Technical and Marketing Notes

- `inference_enrichment.pending` joined `tool_inference` on `(page_id, source_fingerprint)` and kept the misses, so any stored row at all removed a page from every later window until its source bytes changed — including a row whose only content was that Lift Wing returned 503. A burst on 2026-08-26 froze 235 pages that no subsequent sweep could reach. `error` rows now re-enter after `RETRY_ERROR_AFTER = 6h`, ordered behind untried pages by `ToolInference.tool_name.is_(None).desc()`, so a retry can only ever take a slot nobody wanted. Rejections are deliberately not retried: an error is a statement about the endpoint, a rejection is a statement about the answer, and the bytes have not moved.
- 4,253 rows carried `status='rejected'` with an empty `detail`. Each field validator now returns `Checked(value, reason)` and `accept()` is derived from `check()`, so the stored explanation cannot drift from the rule that actually refused the value. Detail is written on `ready` rows too: a reply whose keywords validate and whose description does not stores as `ready` carrying no description, which is exactly the gap this lane exists to close and is invisible in the status alone. A reason is still not evidence, though, and all 4,260 stored rejections recorded one against a reply nobody kept — "description: absent or null in the reply" cannot be told from an HTML error page that happened not to parse. `ToolInference.reply` now stores the model's words wherever `detail` says something was refused, nullable so that NULL means "nobody wrote it down" and `''` means "asked, and nothing was refused". That difference is also the backfill: `pending` gains one arm, `status='rejected' AND reply IS NULL`, which selects exactly the rows predating the column — 3,846 of them still in the join, against a never-asked frontier of 1,866. It is not a change to the no-retry rule. `record` writes the column on every outcome, so a row leaves that arm on its first pass through it whatever came back, which makes "once" a property of the predicate rather than a counter; an errored re-ask lands in the six-hour cooldown instead of consuming its turn. Ordering is three tiers now — never asked, error retry, backfill — so the new arm can only take slots the other two did not want.
- The gadget half — 10,879 records with no description and no inference row ever — was reframed from inference to transcription. Measured across 170 declared gadgets, 91.2% have a `MediaWiki:Gadget-<name>` interface message their maintainer wrote (85% frwiki, 99% Meta). Gadgets are now never sent to the model, and the projection publishes the wiki's own sentence.
- `allmessages` will not enumerate those messages: `amprefix=Gadget-` returns only the twelve extension-registered keys on every wiki tried, with or without `amincludelocal`. The working route is explicit `ammessages=` in batches of 50 with `amincludelocal=1&amenableparser=1`, matched back case-insensitively because MediaWiki normalizes message keys.
- "The wiki did not answer" and "the wiki says nothing" are kept apart throughout. `_descriptions` returns `None` if any batch fails and discards the batches that succeeded; `_store` clears a stored description only when the messages were genuinely read; `wiki_api.messages` drops entries flagged `missing` instead of storing empty strings. The column lands through `db._schema_additions` as nullable rather than `NOT NULL DEFAULT ''`, so adding it to a populated table does not assert that every existing row was read and found to say nothing. The same distinction reaches the job's own output: `gadget_census` now prints `described=` on the `gadget-inventory` line, carrying `None` through as `described=unread` for a wiki whose messages request failed and for one that refused the definition read, because a printed `0` would claim the wiki wrote no description messages. Without it a lane that had stopped transcribing entirely was indistinguishable from a healthy one, and the count had to be recovered by querying `wiki_gadgets` directly. That recovery is no longer manual, because those printed summaries are now kept. The process that knows what a run did cannot write its `job_runs` row — only `job_guard.sh` can tell a child that finished from one killed without a word, and the guard writes the row afterwards — so the two halves meet in a file: the guard names `$STATE_DIR/$JOB_NAME.summary.json`, clears it before the child starts and exports it as `TOOLHUB_JOB_SUMMARY_FILE`, the job writes its summary there, and `job_run_record.py` reads it back. No timestamp matching is needed; the guard's per-job lock already means anything present at exit was written by that child. `JobRun.summary` is nullable for the same reason `wiki_gadgets.description` is: the roughly four thousand rows recorded before the handoff existed, and any run killed before it printed, say nothing rather than say zero. `GET /v1/workers/<name>/` and a page per worker at `/workers/<name>` then show every retained run and what it reported, and chart the `coverage` group over time — `coverage` is the existing convention for figures describing the corpus rather than the run, which is the one thing a number cannot be asked, so a job that reports none gets the run table and no trend.
- `wiki_sources.plain_text` was validated against verbatim frwiki markup rather than composed fixtures, which is what surfaced the two cases worth knowing. `<small>` is the wikis' shared idiom for reference chrome, and a link's label survives resolution while its target does not, so unwrapping the span leaves a catalogue description ending in "[documentation] [illustration]" — the span is dropped whole. Orphaned whitespace is closed up before `.` and `,` only, because French spaces its `:`, `;`, `?`, `!` and `»` on purpose and these messages are mostly not in English.
- Descriptions are published untranslated, in the wiki's own language. The alternative is the catalogue paraphrasing a maintainer instead of quoting one, which is a worse trade than a reader meeting a sentence in French.
- Validation: 3,509 proxy and tools tests with 25 skipped, and 1,374 browser-unit tests; 47 Python tests and 12 unit tests are new across the modules this release touches. Broker gates on the merged tree — jscpd-python, pytest-tools, ruff-check, ruff-format, cspell, prettier, js-quality, pytest-proxy — all pass, promoted as entries 346 through 353.
