# Technical and Marketing Notes

- Shipping `/data-layer` served its own error state to the first person who opened it. The timeline is exact: the release recorded at 17:24:51 and the coverage snapshot was not stored until 17:25:23. In that thirty-second window `ApiCacheMeta` held no row for `catalog_coverage_v1`, and on that path `snapshot()` does not have a stale copy to prefer, so it falls through to `build_snapshot()` — a walk of all 57,352 projections' provenance — inside the visitor's own request. A whole-catalog pass does not fit in a request's budget, so the fetch failed and the view rendered "The data layer report is temporarily unavailable", which is precisely what it is built to say when the snapshot cannot be read.
- The fix is one entry in the deploy's existing prewarm phase rather than a change to `snapshot()`. That phase already warms `/v1/home/`, `/v1/graph/` and the tool summaries under the comment "warm it so the first visitor after a deploy reads a cached row instead of paying for the composition"; coverage was simply never added to it. It gets a 180-second budget, because a provenance pass is far heavier than the composed payloads beside it, and the same non-fatal skip the others use, because a slow prewarm must not fail a release that is already live. Leaving `snapshot()` alone is deliberate: its serve-stale-over-rebuild contract is copied from the statistics snapshot, and relaxing it here would silently change behaviour for both. The cold window is also not a one-time cost — it reopens on any deploy that introduces or resets a snapshot key, which is exactly when a new page draws its traffic.
- The first production run also validated the design's central claim on real data rather than on authored fixtures: `sum(primary) == filled` holds for all nineteen fields across 57,352 tools, so the stacked bars are shares of a real denominator. It surfaced one finding worth acting on separately. The "AI overridden" column reads zero for every field, because the inference pipeline only ever writes into a field that is already empty and never records losing evidence against one that is filled. As implemented the column cannot report anything but zero, so it should either be removed or the pipeline should start recording the suggestions it declines to apply. Validation: `sh -n tools/deploy.sh` passes, the eleven deploy-helper guard tests pass, and the live endpoint now serves the stored snapshot in about 13ms.
