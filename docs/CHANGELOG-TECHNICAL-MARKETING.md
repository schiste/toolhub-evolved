# Technical Release Notes

- Adds a durable digest domain over captured official tool-creation events, immutable edition/tool snapshots, publication state, channel subscriptions, and a restart-safe delivery outbox. UTC day, ISO-week, and calendar-month boundaries are deterministic, generation is idempotent, missed closed periods recover automatically, empty periods are suppressed, and idempotent MariaDB migration widens complete rendered bodies to `MEDIUMTEXT`. Public catalog reads now resolve locally through `/v1/catalog/*`; complete Toolhub snapshots stage by generation and publish in one transaction, failed imports preserve the prior generation, the obsolete request-time HTTP client and revalidation worker are removed, and scheduled workers are the only anonymous Toolhub network readers. Canonical ingestion derives compact card JSON and indexed UTC modification timestamps, background jobs atomically publish global facet aggregates, filtered facets use a covering index and independent endpoint, redundant canonical revalidation is removed, and card rendering no longer waits for facet or summary enrichment. Projection version 4 lifts Toolhub `tasks` and `audiences` annotations without treating API-owned annotations as top-level fields; one shared facet vocabulary preserves legacy `technology` compatibility while exposing canonical `detected_technology`, `declared_technology`, and `ui_language` names across REST and MCP. MCP search uses the atomic local replica, GET `/mcp` returns a structured 405 pointing to a lazy-loaded in-app guide with client-specific configurations, and every new message includes translator documentation. Release notes remain collapsed when no deployment record exists.
- Integrates LiftWing's public OpenAI-compatible `llm-qwen36-27b` chat-completions endpoint with strict Wikimedia host/path/model validation, contact-bearing user-agent headers, bounded timeouts and citation-only payloads, period-wide candidate sampling for busy weekly and monthly editions, Qwen reasoning-tag removal, schema validation, unique supplied-title normalization to canonical tool ids, exact full-field or whitespace-normalized verbatim excerpt evidence checks, and an audited deterministic fallback with sanitized failure details. Daily requests and responses cover every supplied tool exactly once; weekly and monthly responses select exactly `min(total, 5)` tools; omissions, duplicates, ambiguous or invented identifiers, paraphrases, and trivial fragments remain fail-closed. A database-free live preflight exercises production facts through inference, validation, and rendering before deployment.
- Publishes canonical edition pages and the archive tree on Meta through a bearer-authenticated Wikimedia Action API client that restricts destinations, verifies the configured service-account identity, bounds responses, refreshes CSRF tokens, and classifies permanent recipient failures. The same client appends talk-page sections and calls `emailuser` without adding SMTP infrastructure. Configuration-sourced outbound header values are now validated next to the configuration that supplies them rather than inside `requests`: `proxy/backend/http_headers.py` folds interior whitespace runs in descriptive values, because a Toolforge envvar wrapped across lines unambiguously means its single-line form, and refuses whitespace or control characters in credentials, because folding a token would transmit something other than what was configured. Error messages name the variable and never quote its value, which is what makes them safe to return; `WikimediaClient` construction failure is a 500 naming the envvar rather than a 502 that would misdirect an operator upstream, and `LIFTWING_USER_AGENT` is validated inside `generate_editorial()`'s fallback guard so a malformed value degrades to deterministic copy with a recorded diagnostic instead of stopping publication. `WikimediaClient` additionally redacts its access token from transport-exception text, since `requests.InvalidHeader` quotes the offending header value verbatim and that string reaches both the API response body and the stored per-subscription `last_error`. All three 502 branches of `POST /v1/digests/subscriptions/` now log; the module previously imported no logger. The service-account assertion in `csrf_token()` compares MediaWiki spellings rather than raw strings: `WIKIMEDIA_ACCOUNT_NAME=NellieBly_Bot` and the Action API's `NellieBly Bot` name one account, and raw equality made the writer fail to recognize itself and route every write into the permanent `unexpected-account` branch. `canonical_username()` is split out of `normalized_username()` for this, folding underscores, whitespace, percent escapes, and a `User:` prefix while preserving case, because MediaWiki capitalizes only the first letter and casefolding would let a token issued to a different account satisfy the assertion.
- Exposes public edition APIs, local blog routes, per-cadence RSS feeds, authenticated subscription/status APIs, lifetime unsubscribe links, stable Wikimedia identity checks, bounded delivery retries, and per-subscription suspension without cross-channel impact. Email subscriptions activate on subscribe rather than on a confirmation click, matching the talk channel: OAuth establishes the subscriber, the CentralAuth check establishes the account, and `emailuser` only relays to an address its owner already confirmed on-wiki, so a second opt-in verified a strict subset of what those establish while making every subscription depend on a live outbound send that returned 502 when it failed. `send_confirmation()`/`confirmation_url()` are removed; `POST /v1/digests/subscriptions/confirm/` remains and remains idempotent so signed links already in inboxes do not start 404ing. A migration activates rows stranded awaiting a confirmation nothing will send, matching only `confirmed_at IS NULL` so a deliberately stopped subscription is not revived by a later deployment, and stamping `confirmed_at` at migration time rather than backdating it, because delivery gates on `confirmed_at <= edition.period_end` and a backdated stamp would make an already-published edition eligible.
- Adds a compact responsive archive and human-scale edition layout, summary-only archive payloads, accessible subscription controls, localized English strings with translator documentation, immutable permalink and feed discovery metadata, and regression coverage for routes, rendering, confirmation, delivery, RSS, outbound guards, identity trust, and UTC period behavior. Subscription views surface backend failure detail rather than the transport status line: `public_html/views/digests.js` drops a local helper that returned `Error.message` and discarded the JSON body, and calls the shared `backendErrorMessage()` at both the subscribe-submit and confirm/unsubscribe catch sites. `BackendError.message` carries only `Backend ${status} ${path}` by construction, so the three distinct 502 branches of `POST /v1/digests/subscriptions/` — unverifiable CentralAuth identity, `WikimediaAPIError` during the cross-wiki account check, and confirmation-email send failure — were previously indistinguishable in the interface. `backendErrorMessage()` prefers `body.details.message`, then `body.error`, and falls back to `Error.message`, so network failures keep their existing text; it is used in preference to `backendErrorExplanation()` because that helper maps every 502 to a "no official change was published" sentence, which is false for the email-send branch where the subscription row is committed before the 502 is returned.
- Schedules publication at 06:15 UTC, delivery every five minutes, and an hourly audit. Job locks reclaim at twice each timeout; audit failures cover missing configuration, recent Qwen fallback, overdue generation, Meta/archive failure, exhausted delivery, and stale validated or queued work. Due-period scanning is bounded by `DIGEST_BACKFILL_DAYS` (90) and one coordinator pass generates at most `DEFAULT_MAX_EDITIONS_PER_RUN` editions, reporting the surplus as `remaining`; without both bounds the sequential generate-then-publish pass spent its whole timeout walking the catalog back to 2021 and never reached publication. `digest_publish.py --max-editions` raises the cap for a supervised operator backfill without changing the scheduled budget. Push delivery is gated on `published_at - period_end` against `DIGEST_MAX_PUBLICATION_LATENESS_DAYS` (14) — a property of the edition rather than of the wall clock, so it is stable on re-evaluation and identical on every replica — and subscription eligibility compares `confirmed_at` to `period_end` rather than to publication time, which only stood in for it while publication was prompt. An idempotent migration retires previously generated, never-published, never-delivered editions whose period closed before the horizon to a terminal `out_of_scope` status; emptiness rather than nullity is the marker, since the `meta_page_*` columns default to `""`.
- Supports operator-selected historical editions through an internal website-only publication state excluded from Meta, RSS, and subscriber delivery, with no preview or automatic selector. Editions freeze canonical author labels and current verified author/maintainer identities, expose only grounded name arrays to Qwen, and render Toolhub, direct-tool, author-index, and stable-person links deterministically across every output; unverified or expired edges and unsafe identity/link data are excluded before the immutable snapshot is rendered.
- Keeps OAuth account and encrypted-grant persistence atomic and independent from the derived people index. Transient database locks retry or return a controlled login error rather than HTTP 500, while identity reconciliation closes its read session before remote lookups and reconnects for the write phase; the hourly identity-only worker likewise completes remote registry requests before acquiring shared people/user row locks. Complete LDAP generations distinguish immutable `uidNumber`, Developer account `cn`, and Unix shell `uid`; SUL binding remains authoritative, while an unbound account can be verified only by an exact cross-provider handle plus independently verified same-tool evidence. Corroboration indexes include both person-bound relationships and active verified unresolved-attribution rows, while excluding withdrawn, expired, and self-generated LDAP projections. Bare handle matches remain candidates, proof records immutable account and shared-tool evidence, and preloaded indexes avoid per-account reconciliation queries. A fingerprinted Wikimedia user-space reconciliation pass validates allowlisted Wikimedia hosts and canonical `User:` URLs, resolves the page owner to one CentralAuth-stable person, and publishes confidence-95 maintainer evidence for namespace control. It independently publishes author evidence only when the declared author matches. Exact Toolforge matching remains optional account binding; missing, disabled, ambiguous, or conflicting Toolforge identities cannot suppress provider-native Wikimedia evidence. Ownership changes withdraw both roles, and unchanged runs perform no writes. Catalog projection version 3 derives validated user-space `.js` URLs as confidence-95 repository evidence, preserving the direct page as Source code without mutating official Toolhub cache rows or replacing an existing canonical repository. Toolsadmin labels remain attribution unless independently corroborated, legacy label proofs are retired idempotently, unmapped memberships cannot invent catalog tools, and multi-account people are read without cardinality failures. Toolforge runtime and Toolsadmin record URLs now emit confidence-60 unverified project candidates; confidence-100 LDAP maintainer edges require a canonical `toolforge-$PROJECT` name or a valid registered toolinfo source hosted by that project. Content-addressed identity and source-attestation policies force obsolete verified URL-derived edges to be reprojected. A read-time exact-handle candidate projection caps confidence at 60, requires one unique current public owner, folds the matching raw label once, and supplies cards, tool details, directories, legacy routes, and stable person profiles from the same canonical relationship view without writing an identity mapping. All public relationship and unresolved-attribution queries exclude failed, stale, expired, and withdrawn rows; audit evidence remains private. People now receive an immutable Unicode-safe public slug with a UUID-derived suffix, collision extension, an idempotent deploy-time backfill, and a unique database index; the one-time backfill preloads occupied slugs and allocates missing values in linear time before creating the index. The person API resolves either canonical slugs or legacy UUIDs and publishes one canonical path to every frontend projection. Projection policies are content-addressed to force rebuilds after algorithm changes, deep recent-event backlogs checkpoint exact markers instead of failing at 20 pages, vanished upstream cursors preserve every still-visible digest event and start a clean anchored atomic snapshot before rebasing, successful incremental continuity cancels and discards the obsolete staged recovery, and complete catalog snapshots retry bounded upstream count races without pruning from an inconsistent generation. Projection refresh invokes the incremental recent-change and rolling-reconciliation path and shares the catalog advisory lock with scheduled sync and integrity workers; contention becomes a healthy deferred refresh instead of a concurrent staging writer. Parallel account generations release their lock connections before catalog work starts, preserving capacity in the bounded MariaDB pool. Only scheduled integrity or cursor recovery builds a complete generation. Full source audits serialize source-evidence writers and commit bounded retryable batches instead of holding one catalog-wide transaction, while expected refresh overlaps persist as deferred work rather than false failures. Card summaries retain a compact ambiguity-safe projection of every public author/maintainer identity and observed label while excluding full profiles, and statistics expose distinct tool, person, relationship, verification-transition, identity-only, stale, and expiry units. The private My tools payload preserves many-to-many project/account bindings, while a schema-driven browser editor and repository-shipped agent skill generate, validate, copy, and download complete Toolinfo 1.2.2 records without conflating maintainers, authors, core metadata, or API-owned annotations. Adds an anonymous Phabricator profile provider and a `phabricator_real_name` identifier namespace so Toolsadmin-style author labels — which carry the Phabricator `realName`, not the Developer account `cn` — can join to a person. The provider reads only the public `/p/<username>/` page over the shared bounded outbound path against a fixed `PHABRICATOR_BASE_URL`, refuses any handle outside `[A-Za-z0-9._-]{1,64}` before percent-encoding it into the path, treats 404, an unparseable header, and a redirect to another account alike as "no profile", and never turns a transport failure into a cached negative. An hourly `phabricator-realname-sync` job spends its request budget first on the Developer accounts that maintain a tool carrying a name-shaped unresolved author label, then continues a cursor walk over the remaining accounts; priority reads never move that cursor, the cursor advances only past accounts whose every stale handle was read so the SUL-name fallback is never silently dropped, and an outage stops the window on the account that failed. Reads are cached in `phabricator_profile_projection` with distinct 90-day profile and 365-day missing TTLs, and the whole cache is re-judged each sweep so policy changes take effect without refetching. Acceptance is deterministic and fail-closed: the name must come from a `developer_username` or `wikimedia_global_name` handle, exactly one account may publish it, no other person may already own it in a public handle namespace, and a name that only casefolds back to the handle is refused; disabled accounts stay eligible. The namespace is excluded from the public handle list so a sweep cannot read its own prior write as a conflict, corroboration still requires an independent verified same-tool edge from another source, and superseded names are retired idempotently. The Toolforge membership projection now reads tool memberships from the authoritative forward direction: every `(&(objectClass=groupOfNames)(cn=tools.*))` entry under `ou=servicegroups` is paged on the same connection as the account search, and the group DNs each account's `memberOf` list omits are restored before normalization. Wikimedia's reverse `memberOf` index is maintained by an overlay that never backfilled the tool groups created before it existed, so 981 of 6623 real memberships and 666 of 4374 tool groups were invisible — concentrated in the oldest estates, whose feeds therefore had no derivable controller and fell through to `service_registered` at confidence 0. Members that are not people, such as a tool's own service account under `ou=people,ou=servicegroups`, are skipped, and the per-account membership bound rises from 100 to 500 so the restored lists are not silently truncated at the busiest developer's 108 memberships.
