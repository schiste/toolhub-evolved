# Technical Release Notes

- `user_script_directory` and `user_script_directory_members` are deleted and re-inserted wholesale by every projection run, so their row ids are not identities and could not be disclosed. The endpoints now key on `user_script_pages.id`, which survives a rebuild, and emit it as `id` / `filedUnderId`. `GET /v1/userscripts/script/` accepts either `?id=` or `?wiki=&title=`, and a page folded under an original answers 404 with both the origin title and its identity rather than a bare miss.
- Demand was counted by grouping `user_script_imports.target_title` as a string. `UserScriptImport.target_page_id` is now resolved at write time by `resolve_targets`, scoped to the titles one run touched in both directions -- loads made by the pages just written, and loads of them that were waiting. The obvious alternative, scanning every row whose target is null, re-reads the permanently unresolvable rows on every run forever, because a load pointing outside the census never becomes resolvable. `resolve_pending` repairs its own input for readers that cannot know which run should have done it.
- `userscripts.canonical_title` normalizes what a load names before it is stored: underscores to spaces, first letter raised to upper case, namespace aliases folded onto the canonical form. A load naming no wiki means the wiki it sits on, which is what makes Meta's `global.js` corpus resolve at all -- `_targets_wiki` matches both the explicit and the implied spelling.
- Enumeration records the road it took (`replica`, `search`, `search-fallback`) on the census state row, and `enumeration.superseded` re-sweeps a wiki whose recorded road has since been bettered. frwiki had been swept from the search index the day before the replica road landed, 920 pages short, and nothing about watching for changes ever revisits what a wiki was found to hold. It cannot loop: a host where the replica keeps failing records that it fell back.
- Coverage now reports `sweptAt` from the census state rather than from the job's last run, and a watch stamps it too, so a currency figure means the census is current and not that the job is alive.
- A collation-fold collision on one Meta page (`MediaWiki:Gadget-LinkTranslator.js` against `Mediawiki:gadget-LinkTranslator.js`) raised `IntegrityError` out of Meta's ingest and, after three consecutive failures, `job_guard.sh` disabled the census at 10:23 UTC on 23 August. `_replace_imports` no longer predicts the fold -- the tests run on SQLite, which compares bytes and so can never disagree with a prediction -- and instead inserts inside a savepoint, retrying row by row on rejection. The job body now covers each wiki independently and raises `CensusIncompleteError` at the end, so one wiki's failure is still a failure without being the next wiki's.
- `ENUMERATION_QUERY` carries `p.page_latest`, a column on the row it was already reading, out through `Enumeration.revisions`. `ingest` settles a page whose stored revision and `discovery_rank` both match before any content request is made, which is the entire cost of a sweep; an absent revision is treated as the absence of a shortcut rather than as evidence of no change. `_known_revisions` and `_stored_rank` collapse into one `_stored_state` statement, removing a SELECT per page.
- A failed content batch is halved rather than dropped to single titles, which makes `CONTENT_BATCH` safe at the API's own ceiling of 50: one page over the 2 MB response cap costs about six extra requests instead of fifty. `USERSCRIPT_LIMIT` rises 2000 to 6000, which is 120 content requests per run against the previous 100. Validation: 2,684 proxy tests and 1,272 frontend tests pass; ruff check, ruff format, cspell, prettier and jscpd are clean.
