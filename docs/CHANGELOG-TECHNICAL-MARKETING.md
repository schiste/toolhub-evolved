# Technical and Marketing Notes

- The inference lane already read keywords off a user script's source and already stored them, but `FILL_ONLY_SOURCES` kept every one of them out of a list another source had touched, so a tool with one keyword stayed at one while the model's reading sat unused in the evidence panel. Below `KEYWORD_FILL_FLOOR` an inferred keyword may now extend the list, to `KEYWORD_FILL_CEILING` entries in total. The floor reads the list before inference merges, so a tool with two keywords is left alone entirely — two is enough to suggest somebody chose them — and every other list field keeps the original guarantee untouched.
- The fill-only rule exists because lists union, and an unmarked inferred keyword in a curated list is a guess published as a maintainer's word. That objection is about attribution rather than about the value, so the exception is paired with the attribution rather than granted on its own.
- `valueMark` reads the evidence row for one value where `sourceMark` reads it for a whole field. That distinction is the point: a mixed list resolves to whichever row won the field — the maintainer's — so a per-field mark prints nothing at all while displaying the model's words as theirs. A test asserts exactly that, so a later simplification back to a per-field mark fails rather than quietly republishing model output as somebody's own.
- `keywordTags` marks nothing when given no projection. Quickview is such a caller today, and a caller that cannot tell its sources apart must stay silent rather than render a list implying every entry is a maintainer's. The type declares the option so the distinction survives `tsc --checkJs` rather than living only in a comment.
- Three existing tests asserted the old rule, each with its reasoning written down, and were rewritten rather than removed: the never-extends guarantee now stands on `audiences` so it still holds for every field but this one; the append-order test runs both orderings and asserts they agree; and the end-to-end inference test asserts the merged list and that each keyword's evidence still names its real source.
- Validation: 3,722 proxy and tools tests with coverage at 100.00%, 1,401 vitest tests, `tsc --checkJs`, eslint, prettier and cspell clean over 306 files. The effect appears as `catalog-projection` works through the catalogue rather than at deploy, and only for tools the inference lane has already reached; nothing here sends anything new to Lift Wing.
