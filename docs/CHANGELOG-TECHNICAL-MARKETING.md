# Technical Release Notes

- A tenth finding bucket, `browserPermissions`, joins the nine the analyzer already produced, with `browserPermissionCount` in the summary and a `Browser permissions` group in the source-analysis workspace. It is fed from the three places a browser capability is declared and each row carries its family in `category`: `web-api` for the eighteen runtime rules in `BROWSER_PERMISSION_RULES` (clipboard, notifications, geolocation, `getUserMedia`, `getDisplayMedia`, persistent storage, Storage Access, MIDI, Bluetooth, USB, serial, HID, File System Access, wake lock, push, credentials), `extension` for the twenty-four `WEB_EXTENSION_PERMISSIONS` strings and the host match patterns beside them, and `user-script` for `@grant`, `@connect`, `@match` and `@include`.
- The rules are written against their false positives rather than against their examples. Every runtime pattern requires the call and not the object, so `if (navigator.clipboard)` is a feature test and not a request. The manifest family is gated on `_is_extension_manifest()`, which requires `manifest_version` in the file, because a web app manifest and a WebExtension manifest share a filename and only one of them holds permissions. `WEB_EXTENSION_PERMISSION_RE` carries a `(?!:)` lookahead so `"storage"` the permission and `"storage":` the section it configures are not the same finding. `EXTENSION_HOST_MATCH_RE` requires an asterisk, which is what keeps `"homepage_url"` out of the host list. And `@grant none` is skipped: it is the directive that asks for nothing.
- The vocabulary was measured, not assumed. Over the 90,016 pages in en.wikipedia's User and MediaWiki namespaces whose title ends in `.js`, `navigator.clipboard` appears on 110, `Notification.requestPermission` on 19, `// @grant` on 307, `// @connect` on 444, and `getUserMedia` on none. The rare rules are kept — a gadget that turns on the camera is the finding the bucket exists for — but the frequency ordering is recorded in the module so the next reader knows which rules carry the traffic.
- `_browser_permission_signals()` reports the bucket under `permission-clarity` as a `neutral` signal naming up to eight distinct labels, and contributes nothing to the score. The bands in that assessment were fitted against wiki rights and OAuth scopes; letting a new detector move them would have restated every catalogued tool's published health as a change in the tool. A test asserts the assessment score is identical with and without the bucket populated.
- `record_deployment.py` gains `--check`, which runs `marketing_notes()`, `release_metadata()` and `validate_marketing()` and writes nothing, and `.githooks/pre-push` calls it outside the changelog-provider branch. `deploy.sh` applies these rules after the host has already run `git pull`, which is how a nine-bullet technical file aborted the previous release between the pull and the dist build. The rule keeps one definition — a restatement in the hook could drift from what the deploy enforces — and the failure path reports the rule and the two files to edit rather than a traceback.
