# Technical and Marketing Notes

- `available_ui_languages` and `translate_url` are two facts, not one, and separating them is what made the field tractable. The 58 records that already carried languages mean "translated into", with one tool listing 70 -- but only 2% of user scripts use MediaWiki i18n at all. For the rest the honest reading is "the languages its own strings are written in", and the translation link says which of the two a reader is looking at. `translate_url` stood at 12 records of 57,811, 10 of them translatewiki.net, and 8 of those 12 also carried languages.
- Every language, not the first. 6.7% of answered user scripts branch on `wgUserLanguage` and hold their own per-language strings, which is exactly the case the field exists to record. Capped at ten, past which the answer stops being read and starts being recalled.
- The wiki is a poor prior and was measured to be one: only 10 of 31 answers matched the script's own wiki code, so deriving this deterministically from where a script lives would have been wrong two times in three. The prompt names what to ignore -- regular expressions, namespace names, URLs, identifiers, and text a script rewrites rather than shows -- because the obvious signals mislead: a transliteration script is full of Cyrillic it never displays.
- `translate_url` is validated for provenance rather than shape, and it is the only field that is. An invented keyword is a bad tag; an invented URL is a link this catalogue publishes to a page that may not exist, attributed to a tool that never claimed it. It is accepted only when it appears verbatim in the text it was read from, which makes invention structurally impossible -- `Field.needs_source` exists for this one case, and a test asserts nothing else uses it.
- A reply that never parsed no longer counts as asked. `asked_signature` records questions put, and filing an unreadable reply as one retires that question on that row for good: 118 rows had been retired that way, and this field would have retired thousands before the prompt settled. A declined field still counts, because refusing is an answer.
- Measured on the live endpoint before shipping: 40 user scripts asked only the two new fields returned 40 readable replies -- against 14 of 60 unreadable with an earlier standalone prompt at the same token budget. 18 named a language (`en 9, bn 3, ar 2, az, ca, zh-hans, fr`), and no `translate_url` was accepted, which at a 0.1% base rate is what 40 scripts should produce.
- Validation: 3,686 proxy tests with `inference_enrichment` at 100% statement and branch coverage. Three existing tests were widened rather than patched -- the prompt-length bound is now measured against the composed questions instead of a fixed margin, so the next field to join `FIELD_ORDER` does not break it.
