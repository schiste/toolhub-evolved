# Technical and Marketing Notes

- `toolinfo-source-index` writes `tool_relationship_evidence`, which six jobs contend on, and is one of two that genuinely failed on MySQL error 1205 rather than absorbing it. `run_job` has carried `retry_on_lock_timeout` since the people-reconcile work and this job never opted in — it could not. The budget is half a declared timeout, `jobs.yaml` declared none, and `lock_retry_deadline_seconds` returns zero without one rather than inventing a ceiling, because a budget invented for an unbounded job is how a retry runs past a limit it never knew about.
- So the timeout came first: 900s against a measured maximum of 392s across the last twelve runs, read from the `job_runs` table rather than estimated, giving a retry budget of 450s. `--stale-after 1800` travels with it, because a job killed at its timeout cannot release its own guard lock and a timeout without a reclaim threshold leaves every later run skipping on a lock held by a dead process. That coupling is enforced by `test_every_job_with_a_timeout_reclaims_its_lock_at_twice_that_timeout`, which caught the omission — an invariant of that kind belongs in a test rather than a document. The budget helper now lives in `job_runner` and `people_reconcile` delegates to it, so one rule has one home.
- The previous release notes are corrected here rather than quietly rewritten. They claimed 179 failed runs across ten jobs including 72 in `maintainer-backfill`; the accurate claim is 179 logged lock-wait events of which an unknown fraction were absorbed. `maintainer_backfill` wraps its per-tool write in `db.run_with_lock_retry` and recovers, which its guard streak confirms — it never left zero through the entire episode. `people-identity-reconcile` and `toolinfo-source-index` are the two that genuinely failed, and only the second lacked a retry.
- `tests/tools/test_job_command_signals.py` interpolated the guard path into a shell string unquoted, so it could never pass in a broker worktree: every one lives under a directory whose name contains a space, the path split into two words, the guard was never started, and the failure reported that the guard had not taken its lock. All three interpolations are quoted now; the two output redirects carried the same latent bug and only worked because pytest's `tmp_path` has no spaces. The repository instructs all work to happen in broker checkouts of that kind, so this test was failing in the environment it is meant to be run in and passing only in the one nobody is supposed to use.
- Validation: `tests/proxy` and `tests/tools` together, 3,714 passed and 25 skipped. Two new tests pin the coupling that made this awkward — an undeclared job gets a zero budget, and this job's budget must stay above zero, so removing the timeout fails the suite rather than silently disabling the retry it pays for. The signals test now passes in a broker worktree in 0.07s where it previously failed three times out of three after a ten-second wait. `ruff check`, `ruff format` and `npm run spell` clean over 305 files, graph index regenerated with the pinned 0.4.2 pair.
