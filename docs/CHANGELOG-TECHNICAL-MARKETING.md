# Technical and Marketing Notes

- `/statistics` reports how much of the catalogue is filled; the new `/data-layer` page reports who filled it. Every field on a `CatalogToolProjection` already carries the ordered evidence that produced its value, so the attribution had been recorded since projections existed and was never surfaced. A new `backend/catalog_coverage.py` walks that evidence for the whole catalogue in one pass, stores the result under the `catalog_coverage_v1` snapshot key beside the statistics snapshot, and serves it from `GET /v1/coverage/` — public, `max-age=300`, ETag-revalidated, counts only and no values. `projection_refresh` rebuilds it as a final stage after it has rewritten the projections, so the whole-catalogue pass stays off the request path; a request rebuilds only when nothing is stored or the copy is over six hours old, and then only if it holds the advisory lock, so a crowd arriving at a cold cache does not stampede the pass. The query names its two columns and streams at `yield_per=500` rather than selecting entities.
- The eight precedence sources collapse into four audience-facing buckets — human, toolinfo, code, ai — because the eight are a vocabulary for resolving conflicts, not for reading. The problem that shaped the module is that this cannot be counted naively: a field carries several evidence entries, and a list field can be merged from several sources at once, so attributing a field to every source that touched it makes the buckets sum past the number of filled fields and turns the stacked bar into shares of a number that does not exist. `_primary()` picks exactly one entry per field, the highest-confidence effective one, breaking ties by observation time; the remaining contributors are reported separately as `contributing`. That single choice is what makes `sum(primary) == filled` hold, and the bar is only honest because it does.
- `code` is kept separate from both `toolinfo` and `ai` because the three behave differently under precedence, and folding them would have hidden an analyzer's guess inside a tool's own declared metadata. Only `llm_inference` is fill-only, so it can never displace a value another source stated; `repository_analysis` asserts at confidence 75 and can become the effective value of a field nobody else filled. The same asymmetry pays for the "AI overridden" column: a bucket that supplied evidence but lost the field is counted as `shadowed` rather than silently dropped, so the page distinguishes what the model wrote from what it wrote and was overruled on. Validation: 3,463 proxy tests pass with 25 skipped, twelve of them new. Six cover the snapshot — every source maps to a bucket, the buckets sum to `filled`, a shadowed AI value is not counted as filled, a list field merged from two sources counts once, unready projections stay out of the denominator — plus the endpoint's public cacheability and its 304 revalidation. Six cover the view, including that each row's segment shares sum to 100 and that the shadowed count renders while the AI segment stays at the share it actually won. Both `projection_refresh` stage-ordering tests now assert coverage runs last, and the route is added to the `/v1` guard allowlist so it cannot go unguarded unnoticed. 1,368 unit tests pass; eslint, stylelint, prettier, cspell, banana-checker, `ruff check`, `ruff format` and `i18n:check` are clean.
