# Technical Release Notes

- `userscript_census.enumerate_titles` short-circuits at `SEARCH_OFFSET_CAP` (10,000) and returns one `SEARCH_PAGE_SIZE` page with `complete=False`, so Meta's javascript census held ~500 of 25,354 titles. The remedy the module's own docstring prescribed does not exist: probed live against Meta, one negated `prefix:` clause partitions the index exactly, a second is silently dropped, and two positive ones return zero. CirrusSearch cannot be made to prove it named everything.
- New `backend.userscript_enumeration` prefers one indexed replica read -- `page_namespace = 2 AND page_content_model IN ('javascript','css') ORDER BY page_id` -- and falls back to the search road on any failure, an empty result included, because an enumeration that names nothing and calls itself complete is the one answer that would tombstone a whole wiki. Measured from Toolforge: 155,561 enwiki rows in 13.2s. `page_id` order is creation order, which is what `discovery_rank` wants, for free.
- The replica road costs one `meta=siteinfo` request per wiki. The replica stores `page_title` without a namespace and with underscores; the API answers frwiki titles as `Utilisateur:`, not `User:`. Ranks, revision-skipping and tombstoning all key on the title, so requesting under the canonical prefix would have zeroed every rank and tombstoned every stored frwiki page. The road refuses to proceed when a wiki will not name namespace 2.
- `sweep()` takes a `limit` and each wiki carries a `sweep_cursor`; `ingest()` takes a `rank_offset` so a slice records absolute ranks rather than renumbering from zero. Only the run that reaches the end tombstones missing pages or counts as a completed sweep. A cursor is dropped when the enumeration is incomplete or points past the end -- both restart from zero, which costs a pass and cannot silently skip pages. enwiki joins at `USERSCRIPT_LIMIT=2000`, and needs no `LOCAL_LOADERS` entry: its `Common.js` defines no load verb.
- `job_guard.sh` traps HUP/INT/TERM, but on Toolforge those traps never ran. The framework composes each command as `/bin/sh -c -- 'exec 1>>...; <command>'`, so the wrapper shell owns PID 1 and the guard runs as its child -- PID 7 in a live pod. Kubernetes signals PID 1 only, a shell with no trap waiting on a foreground child passes nothing down, and the guard was killed outright after the 15s grace period with its lock still held: 24 `reclaiming ... lock abandoned ~3600s ago` lines, two after the release meant to have fixed it. Every command in `jobs.yaml` is now prefixed with `exec`.
- `upsert_records` queued every fetched name for people reconciliation regardless of whether the stored record changed, so each recovery snapshot enqueued 4,501 unchanged tools into a lane that drains 25 a minute by design -- about three hours at its ceiling, generations 44 through 49 each retiring none. It now compares the whole record, not the fields reconciliation happens to read today, and queues only what moved. Reconcile phases now report their own timings.
