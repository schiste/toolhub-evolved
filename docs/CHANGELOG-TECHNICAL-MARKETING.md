# Technical Release Notes

- `userscript_projection.candidates()` selects seven named columns rather than ORM `UserScriptPage` rows. A `Candidate` carries a title, owner, basename, creation key, fingerprint and sketch, and the last two are already distilled from the body at census time, so loading page objects dragged 56,206 enwiki script sources into memory to read titles off them. Measured on that corpus, the projection's peak RSS falls from 806MB to 354MB.
- `project()` is now read / fold / write, holding no database connection across `directory.collapse()`. The fold is pure Python and roughly 90 seconds of it on enwiki; a session held open and silent through that is one ToolsDB is entitled to close, and it did -- the run then died on the first query of the write with `(2006) MySQL server has gone away`. `pool_pre_ping` was already enabled and cannot help, because it validates a connection at checkout rather than one already held. The three transactions cost no atomicity that existed: the projection has always rebuilt derived rows from a corpus the sweep is changing underneath it.
- `userscript_sweep.ingest()` reads and commits a window in `INGEST_CHUNK` slices of 500. `USERSCRIPT_LIMIT` answers how much of a wiki a run covers, which is a question about request budget; `INGEST_CHUNK` answers what that costs to hold, which is a question about the container. They were the same number until enwiki proved they are not, and separating them also makes a killed run keep what it had already written.
- `jobs.yaml` gives the census `python -u` and an explicit `mem: 2Gi`. The cluster's unstated 512Mi default sits between the 806MB and 354MB peaks, which is why the scheduled runs were SIGKILLed before they could ever reach the connection error -- and why buffered stdout meant the log of a run that died mid-phase was indistinguishable from a run that never reached it.
- Four regression tests, each confirmed to fail against the previous code: no `user_script_pages.body` in any SQL the projection emits, zero pool checkouts held while the fold runs, a window read in bounded slices however large it is, and a run interrupted mid-window keeping the slices it had committed.
- Repository tooling moves to the official Aethyme v0.2.0 deployment policy: generated `AGENTS.md` and `CLAUDE.md`, `.claude` and `.codex` skill trees, a context-loading hook and a CI workflow. It touches no application code, job definition or web asset.
