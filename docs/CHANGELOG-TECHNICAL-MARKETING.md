# Technical and Marketing Notes

- `userscripts.strip_comments` applied the block-comment rule and then the line-comment rule, two independent substitutions over the same text. `//` and `/*` are alternatives of one left-to-right scan, and running one pass first imposes a precedence the language does not have: a `/*` already inside a `//` line opened a block comment anyway.
- `User:Yug/RenameOrReplace.js` on meta is the reported case. Its Tampermonkey header carries `// @match https://commons.wikimedia.org/*`; the trailing `/*` matched to the file's next `*/`, blanking 17,079 of 17,240 bytes. Four header lines survived, all of them line comments, so `_code_lines` returned nothing and `classify` returned `ROLE_EMPTY`.
- `userscript_projection.candidates` filters on `role == ROLE_SCRIPT`, so the page was never a directory candidate and never a collapse member either — which is why the API answered `no such script in the directory` rather than `not an original`. The same strip feeds `fingerprint` and `sketch`, so a truncated page was also hashed from its four surviving header lines.
- The pattern is now `(?<![:'"])//[^\n]*|/\*.*?\*/` under one `sub`. It does not solve `/*` inside a string or regex literal, which no regex can and which the existing comment already documents; it corrects the ordering error only.
- Fixing the analyzer alone would have changed nothing already stored. `_settled` skips a page whose revision has not moved, and an abandoned script's never does, so a wrong verdict was permanent. `userscript_sweep.restate_analysis` re-derives role, fingerprint, sketch and load edges from the stored body — the reason bodies are kept — and asks no wiki, so `revision`, `touched_at_wiki` and `last_checked_at` go on describing the read that fetched it.
- The deploy migration walks the rows that could have been truncated: non-script role, not tombstoned, body containing `/*`. All three non-script roles rather than just `empty`, because a swallow leaving one line behind reads as a stub and one leaving a load behind reads as a shim. It writes only where the verdict moves, so a second deploy writes nothing, and it walks by id at a quarter of `BACKFILL_CHUNK` because bodies run to 512 KiB and this runs inline during a deploy. A body stored at that cap is declined outright: `store_page` analyses the whole page and truncates only what it keeps, so restating from the remnant would trade a verdict about the script for one about its first half megabyte.
- Corpus shape, from CirrusSearch over ns-2 `.js` pages: an unclosed `/*` inside a `//` line appears on 400 enwiki pages, 59 on meta, 57 on frwiki, 22 on commons. Not all lose everything — the swallow also needs a later `*/` — and in a 60-page sample of meta pages carrying the broader shape exactly one was misclassified.
- Validation: 3,410 proxy tests, 25 skipped, eight of them new. Against the live wiki the fixed analyzer returns `script` for the reported page and leaves the other eight pages in the same user space on their existing verdicts: two scripts, one archived script, three shims, one stub. ruff check and format over `proxy`, cspell over the changed sources.
