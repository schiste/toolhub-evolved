# Technical and Marketing Notes

- The creation-date lane was already standing on the answer. `CREATION_QUERY` folded `MIN(rev_timestamp)` per page, and an aggregate returns a value that structurally cannot name the row that produced it — so the revision carrying the actor was visited and discarded on every pass. The query now names that row instead: `JOIN revision r ON r.rev_id = (SELECT r2.rev_id FROM revision r2 WHERE r2.rev_page = p.page_id ORDER BY r2.rev_timestamp, r2.rev_id LIMIT 1)`, with `LEFT JOIN actor a ON a.actor_id = r.rev_actor` riding along. That reads less, not more: one index dive per page over `(rev_page, rev_timestamp)` in place of folding every revision the page ever had.
- The candidate SQL was measured against the live frwiki replica before a single fixture was written. Namespace 2, `%.js`/`%.css`: the new form returns the same 14,433 rows in the same second as the old `GROUP BY`, and 0 of those pages lack a readable first author. The owner-versus-author divergence is 954 rows, 6.6%. A first pass put it at 23% — `page_title` stores `Dr_Brains` and `actor_name` stores `Dr Brains`, and comparing them naively invents mismatches that are not there.
- `first_author_wiki` lands on `user_script_pages`, `wiki_gadgets` and `user_script_directory` through the idempotent additive DDL in `_schema_additions()`. User scripts fall back to the title owner where no replica has answered, so a host without `replica.my.cnf` publishes exactly what it published before; gadgets have no owner to fall back to and publish no `author` key at all when the field is blank, which is a strict gain over the nothing they carried previously. `rev_deleted & 4` — MediaWiki's username-suppression bit — is filtered in SQL via `IF(r.rev_deleted & 4 = 0, a.actor_name, '')`, so a suppressed revision keeps its date and contributes no name.
- The subtle defect was in the backfill filter, not the query. `pending()` selected pages with `created_at_wiki == ""`, and the census is effectively 100% dated — so on the first run after this change the lane would have declared the entire corpus settled and never attributed a single existing page. It now selects rows missing _either_ field, which drains to zero once both are filled and costs a fully stamped page no write.
- Gadget attribution is deliberately narrower than "fill it if it is empty". A gadget's date is the oldest of its declared pages; if a declaration drops the file that dated it, the stored date belongs to a page no longer declared. `apply_origins` therefore takes the author only when the oldest page's stamp is earlier than the stored date (the date moves and the credit moves with it) or exactly equal to it (the dating page is still there). A gadget whose dating page left the declaration keeps its date and stays unattributed rather than borrowing a name off a different edit.
- Validation: 3344 passed, 25 skipped across `tests/proxy`, up from 3323. The first draft of `read_page_origins` guarded the author column with `len(row) > 2`, which existed only so the pre-existing two-column fixtures would keep passing — a test that cannot see the new field cannot fail on it. The guard was removed and all 21 affected fixtures widened to three columns. ruff check, ruff format --check and cspell clean.
