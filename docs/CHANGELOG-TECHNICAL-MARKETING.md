# Technical and Marketing Notes

- Shipping `/data-layer` served its own error state to the first person who opened it. The release recorded at 17:24:51 and the coverage snapshot was not stored until 17:25:23; in that window `ApiCacheMeta` held no row for `catalog_coverage_v1`, and on that path `snapshot()` has no stale copy to prefer, so it fell through to `build_snapshot()` — a walk of all 57,352 projections' provenance — inside the visitor's own request. The fix is one entry in the deploy's existing prewarm phase, with a 180-second budget and the same non-fatal skip the calls beside it use. Leaving `snapshot()` alone is deliberate: its serve-stale-over-rebuild contract is shared with the statistics snapshot, and relaxing it here would change both.
- The page's "AI overridden" column is removed. It read zero for all nineteen fields and structurally always would: `llm_inference` is the only source in `FILL_ONLY_SOURCES`, so it is written exclusively into fields that are already empty and never records a suggestion it declines to apply. The backend `shadowed` tally stays in the payload, because only its AI slice is empty — `repository` alone carries 37,760 human-sourced values that canonical toolinfo overrode — and those deserve a view that reports all four buckets rather than one.
- `license` was the worst-covered substantive field in the catalogue at 10.1%, and every one of the 10,879 wiki-hosted user scripts and gadgets was missing it. They are not unlicensed. Section 7 of the Wikimedia Terms of Use binds text contributed to any project under CC BY-SA and carves out nothing for JavaScript or CSS — the words never appear — and no project supplies a different rule, `Wikipedia:User scripts` included. Reading that off is a transcription of a declaration the author made by publishing, which is why it belongs in the wiki toolinfo builders beside `created_date` rather than in the inference lane.
- The version is the part worth stating precisely, because the obvious answer is wrong. The current Terms took effect on 7 June 2023 and cannot relicense a contribution already made, so a page first written in 2009 is CC BY-SA 3.0 today, not 4.0. `wiki_sources.content_license` therefore takes the creation date and returns 3.0 or 4.0 across that boundary — creation rather than last edit, because an edit in 2024 adds 4.0 material to a page whose earlier revisions stay 3.0, and the licence binding the whole page is the older one. An undated page publishes nothing, exactly as `created_date` does: which version applies is a question about when, and 3.0 is still a guess without one.
- Measurement drove that decision rather than following it. Of 120 enwiki user scripts sampled, 102 were created before the boundary; of the ten most-installed scripts on enwiki, all ten resolve to 3.0, so a flat "CC BY-SA 4.0" would have mislabelled every headline entry in the corpus. A separate scan established there was nothing better to read: across 409 enwiki script pages, zero carried an SPDX identifier and two used the word "licence" at all. Precedence is unchanged and already correct — canonical toolinfo scores 100 against the wiki sources' 95 and 90 — so any tool that does declare a licence keeps it, and a curation can still correct a page that mirrors an externally licensed project. The note in `source_hosts._mediawiki_metadata` that reads as a blanket refusal of any wiki-derived licence now says what it actually refuses: the API's display banner, which is unversioned and page-agnostic, as distinct from the dated Terms of Use read.
- Validation: 164 proxy tests pass across the projection, validation, sweep, docs and inference suites, plus 151 across the two toolinfo builders and `wiki_sources`, with the 7 June 2023 boundary pinned from both sides. `uvx ruff@0.16.3 check proxy` and `format --check proxy` pass, and cspell is clean. The first sweep after deploy rewrites roughly ten thousand records once, because `_write` diffs on `row.record` and the new field makes each one genuinely differ; subsequent runs count them unchanged.
- The whole-tree Python coverage ratchet is met for the first time since it was set. `fail_under = 100` has been the coverage floor since 13 August and CI had been failing on it, unnoticed, for 266 commits: the gate protected `main` and nobody read the result. The suite now reports 20,206 statements and 5,774 branches with nothing missed, over 3,567 tests. About half the shortfall was tests nobody had written; the other half was code that could not run. Seven defensive guards were deleted rather than pragma'd -- the blank-slot checks in `source_analyzer` that `GadgetEntry.values` already strips, a `None` clause in `_expire_where`, the empty-licence fallbacks in both wiki toolinfo builders -- each replaced by a comment naming the invariant that rules the branch out, because a pragma hides an unreachable branch where deleting it states why. `pragma: no cover` stays reserved for `__main__` entrypoints. The quality jobs also install their own tooling now, from a pinned `tools/python-quality-requirements.txt` and a checksum-verified Aethyme pair, so a green run reflects the repository rather than whatever the runner happened to have. Two of the report views also stopped carrying byte-identical copies of the same count and date formatters, which is the duplication the JavaScript gate exists to catch. The secret scanner was reading wider than its own comment claimed: gitleaks combines allowlist criteria with OR, so the placeholder vendor key the source-analyzer fixtures need in order to be scanned was exempt everywhere in the repository, production configuration included. It is now bound to the two fixture files with `condition = "AND"`, and a planted key outside them is caught again.
