# Technical and Marketing Notes

- 69 rows in `repository_analysis_state` sat at `attempts=11` — the ceiling of the doubling backoff, `MAX_BACKOFF_DOUBLINGS = 10` against a 720-hour cap — carrying `fatal: could not read Username for 'https://github.com': terminal prompts disabled`. `GIT_TERMINAL_PROMPT=0` is set deliberately in `_git_raw`; the service holds no forge credentials and is not meant to. Nothing reachable from here could ever change those rows, and they were re-asked monthly, forever.
- The cost being removed is not throughput. The refusal comes back from `ls-remote` — one round trip, before `_decide`, long before a clone — which is exactly why the backoff shipped in the previous release never resolved them. What is removed is a row that lies: `status = "error"` is read everywhere downstream as a failure that will clear, and this one cannot.
- New terminal status `RESTRICTED = "restricted"`, set from `scan_tool`'s exception handler when `_needs_credentials()` matches git's own wording (`could not read username/password for`). `_save_restricted` clears `next_attempt_at` and increments `attempts`, so the row still records what the verdict cost. `_settled_restricted` keeps it out of the backlog stream in `partition_candidates`, keyed to the repository URL exactly as `_settled_unsupported` is — a record edited to name a readable repository is scanned again; one that does not move stays settled. `run(tool_name=..., force=True)` goes through `candidate_tools`, which never consults the verdict, so re-deciding a single row on request stays a one-liner.
- The predicate matches git's message rather than an exit status. Exit 128 covers ordinary transport failures too, and settling one of those would drop a live repository out of the catalog for good — so a `503` is asserted to still receive a backoff. `last_error` keeps git's sentence rather than a fixed reason string: unlike `UNSUPPORTED_HOST` and `NO_SOURCE_REASON`, which are verdicts this code reached on its own and had to word itself, this one has real upstream evidence naming the host that refused.
- GitHub answers private, deleted and moved-behind-auth identically, on purpose, so that asking cannot reveal which. "Not publicly readable" is therefore the whole truth available, and it is a fact about the URL rather than about the run that hit it — which is what makes the URL the right key and `_save_unsupported` the right sibling to mirror.
- No migration and no data reset. Each of the 69 rows is reselected once when its existing backoff expires, refused again, and settles itself; the count drains without intervention.
- Validation: 3350 passed, 25 skipped across `tests/proxy`, up from 3344. The new tests were checked by mutation rather than assumed — reverting the exception routing fails 3 of them and reverting the `partition_candidates` guard fails 2. One earlier draft asserted only that a moved record reappears in the backlog, which passed with the verdict ignored entirely; it now asserts the contrast, a moved tool present and an unmoved one absent, so the comparison itself is what is under test. ruff check, ruff format --check, cspell and prettier clean.
