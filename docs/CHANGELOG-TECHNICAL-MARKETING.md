# Technical and Marketing Notes

- `backend/source_authorship.py` is a pure module: marker paths and commit identities in, `{llmAssisted, provider, model, assistants, signals}` out. No I/O, no file contents — a path listing and what `git log` already holds. `RepositoryAnalysisState` gains `llm_assisted`, `llm_provider`, `llm_model` and `llm_checked_at`; the signals behind each verdict go into the stored report, so a reader can disagree with the conclusion rather than only accept it.
- The verdict is `True` or NULL, never `False`. Absence of these traces is evidence about these traces, not about authorship, and a `False` in a column named `llm_assisted` would be read as "a human wrote this". `llm_checked_at` carries what the verdict cannot — that the layer looked — which is also what makes the backfill terminate rather than re-clone the catalogue on every run.
- Detection reads the `ls-tree` listing, not the files the analyzer received. That set is capped at `MAX_FILES` and ordered by analysis value, so a repository of a few thousand files can push its `CLAUDE.md` out of it entirely. The listing has no cap, was already fetched, and opens no blob — one extra local `ls-tree` against a pack on disk, beside a network clone.
- It runs before the caller-supplied `repositoryContext` is merged, so no request body can assert that somebody else's tool was written by an assistant. What a caller can still do on `/v1/source-analysis/` is name a file `CLAUDE.md` — the same latitude it has over every other conclusion drawn from files it supplies, and why that lane stores its reports for review.
- Precedence when the evidence splits: a commit identity outranks a marker file, because one is a record of the tool writing something and the other of it being configured. Two vendors at the same rank leave the column empty rather than picking one — both were involved, which the signal list can say and a single column cannot. A model is recorded only from a signature that states one; `Claude Opus 5` in a trailer is a model, bare `Claude` is a tool.
- `repository_scan.py --authorship-backfill` selects `status = 'analyzed' AND llm_checked_at IS NULL`, joined, ordered and limited in one statement that names two columns rather than selecting the entities. Forced, necessarily: every row in that backlog sits at a commit that has not moved, so the ordinary re-check would skip all of them. A row that fails leaves `analyzed` on its way to `error`, so the selection shrinks monotonically.
- No new index, so nothing here goes near MariaDB's 3,072-byte key limit — the guard test added last release covers that either way. The four columns are nullable additions through `_schema_additions`, with no `DEFAULT` on `llm_assisted`: a default would have silently declared several thousand not-yet-read tools assistant-free at `ALTER` time.
- Validation: `pytest tests/proxy -q` 3203 passed / 25 skipped. Twenty new — twelve over the detection rules, four that scan real one-commit repositories built in a tmpdir so the git parsing is exercised rather than mocked, two over the backfill selection, and two over the analyzer lane including the one that proves a caller cannot assert a verdict.
