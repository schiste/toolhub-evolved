# Technical Release Notes

- `Finding.confidence` is now a derived property rather than a field mutated by `add()`. Each sighting records the best source weight per distinct path in `path_weights`; the property takes the top corroborating weights above `HIGH_PROVENANCE_WEIGHT`, caps them at `CONFIDENCE_MAX_CORROBORATING_FILES`, and adds the boost once. Previously the boost was applied incrementally at insertion time, so the three-file cap consumed whichever files arrived first: the same repository read in a different order reported different confidences and a different `for_wikis` order. Repeated mentions inside one file no longer corroborate anything, and the payload carries `fileCount` so a caller can see how many files a claim rests on.
- Publication is gated on corroboration. `_is_corroborated()` passes a finding only if it comes from a file at or above `PUBLICATION_TRUSTED_SOURCE_WEIGHT` (0.85 — manifest, runtime, lockfile, frontend, config) or appears in more than one file, and `_corroborated_rows()` applies it to the suggestion path. The gate is deliberately not applied to `_publishable_rows()`, which also feeds assessment scoring; putting it there would have silently moved every health score rather than changing what the directory asserts about a tool.
- `healthCore.confidence` is now the weight-weighted mean of the scored dimensions' own confidences instead of a function of how many dimensions were scored, and `grade` is withheld as `unknown` below `HEALTH_MIN_SCORING_CONFIDENCE` (0.6). A repository containing one `print(1)` scored 43 / high-risk at confidence 0.81 while its dimensions reported 0.1–0.68 — the composite was measuring the arithmetic, not the evidence. `unknown` was already a first-class grade in `tool-health-summary.js`, so the frontend needed a message change and no new vocabulary; the score and every dimension are still reported alongside the withheld grade.
- File selection reserves capacity instead of running first-come. `CONTEXT_RESERVE_SLOTS` (20) and `CONTEXT_RESERVE_BUDGET_DIVISOR` (6) hold back part of the `MAX_FILES` / `MAX_TOTAL_BYTES` budget for classes that were being starved. Repositories with large manifest sets were exhausting both caps before reaching docs, CI or tests, and the readiness dimensions that read those files scored zero for absence of input rather than absence of practice — indistinguishable in the output.
- `for_wikis` is a closed vocabulary. The database-name pattern was matched against arbitrary identifiers, so build targets, SQL table names and config keys landed in a field the catalogue publishes; candidates are now resolved against the real project list and dropped if they do not resolve.
- The toolinfo crawler distinguishes absent from unreachable. An upstream request that fails now records an explicit unreachable state rather than collapsing into the same result as a successful 404, which is what made a Toolhub outage look like a catalogue in which our tools do not exist.
- `test_source_analyzer_corpus.py` runs the analyzer over this repository's own `git ls-files` and asserts invariants rather than values: evidence paths are a subset of what was supplied, `fileCount` is at least the number of distinct evidence paths, `maxSourceWeight` bounds the per-evidence weights, grade and band agree including the withheld branch, composite confidence never exceeds the strongest dimension, and two runs over a shuffled file list agree exactly. The order-dependence above was found by that last assertion, not by review.
- `source_analyzer.py` is split along seams it already had: `source_analysis_common.py` (constants and the eleven helpers shared by both lanes) and `source_analysis_assessments.py` (the eight assessments, seven health dimensions and stewardship). The move was verified by comparing the AST of every top-level definition before and after — nothing lost, added or changed in body. The scanning rules were left where they are: unlike the two extracted blocks, they interleave with the rest of the module rather than sitting contiguously, so extracting them would have been a scatter-gather rather than a move.
- `userscript_sweep._replace_imports()` returns the number of rows the database refused as duplicates of another edge on the same page, `store_page()` passes it up, and `ingest()` accumulates it into the new `collisions` key of `EMPTY_COUNTS`. The bulk insert is still attempted first and still falls back to per-row inserts on failure -- one page's spelling is not a reason to fail a wiki -- but the fallback now counts what it drops instead of discarding it silently. It has to be observed rather than predicted: which titles collide is decided by the database's collation, not by this codebase.
