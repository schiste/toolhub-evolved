# Technical and Marketing Notes

- The MediaWiki Action API answers in the wiki's own language. An `allpages` listing on de.wikisource returns `Benutzer:PDD/unsigned.js` for the page this service stores canonically as `User:PDD/unsigned.js`. `repository_scan._wiki_revisions` filtered the fetched revisions against the canonical spelling by string equality, so on any wiki that localizes its namespace label every revision it had just downloaded was discarded and `_acquire_wiki` raised "wiki page set holds no readable revision". 18,520 of 18,719 repository-analysis errors were that one message.
- The failure split perfectly by wiki, which is what made it diagnosable rather than a long tail: en.wikipedia analyzed 8,686 scripts against 31 errors, fr.wikipedia analyzed 0 against 1,243. Every wiki on the passing side (en.\*, meta, zh, wikidata, commons, test, simple) uses the literal label `User`; every wiki on the failing side localizes it. The gadget lane was untouched because it fetches explicit titles via `pages_url` and does no filtering at all.
- `wiki_sources.listed_title` rewrites a listed title's namespace label into the canonical one, and both sides of the membership test now go through it. This is a rename, not a guess: the listing was restricted by `gapnamespace` — `source.namespace_id`, a number — so every result is in that namespace whatever the wiki calls it locally. `canonical_title` alone cannot do this, because asked about a title from nowhere in particular it cannot distinguish an unfamiliar namespace from a page name that merely contains a colon, and must leave the prefix alone. A title whose labels already agree is returned untouched, so the English wikis keep the exact path they had.
- Reports still name pages in the wiki's own spelling. `analyzedPaths` carries `Benutzer:Example/twinkle.js`, not the canonical rewrite, because that is the string a maintainer on that wiki can act on; the canonical form exists only to make the comparison possible.
- Validation: two end-to-end regressions in `test_repository_scan.py` (a localized listing analyses both its pages; a localized neighbor by the same author is still excluded) and three in `test_wiki_sources.py`. Reverting `listed_title` to `canonical_title` fails four of the five. Two further tests written for this were deleted rather than shipped — `subpage_titles` always prepends `source.title`, so a single-page localized listing passes even mutated, and a test that cannot fail is worse than no test. Full proxy suite 3323 passed, 25 skipped; jscpd, ruff check, ruff format, cspell and prettier clean.
- No data reset is required. The affected rows carry 4 to 6 attempts against a doubling backoff capped at 720 hours, so their next attempts are already spread across the following two days and they recover unattended once the fix is live.
